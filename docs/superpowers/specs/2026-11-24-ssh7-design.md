# SSH7 — 设计规格

> 用 Rust 重写 SSH 客户端 LuciSSHClient，视觉语言参考 cindy.cn。
> 状态：待评审 · 日期：2026-11-24 · 上游项目：LuciSSHClient（Electron + React + ssh2）

---

## 1. 目标与非目标

### 目标

1. **核心逻辑全部 Rust 重写**：SSH 握手与会话、SFTP 文件操作、密钥与密码存储、目录跟踪，全部由 Rust 实现，前端只负责渲染与输入转发。
2. **视觉重新设计**：采用 cindy.cn 的设计语言（Ink 黑 / Cream 米白 / 信号红），不是把旧样式换色。
3. **功能与旧版对齐**：多会话终端、SFTP 文件管理、拖拽上传 / 下载、保存主机、连通性测试。
4. **修掉旧版全部已知缺陷**：见 §6 缺陷清单。
5. **开源发布**：GitHub 公开仓库 `chuaker7/SSH7`，MIT 协议。

### 非目标

- 不做端口转发、会话录制、批量分发（本轮范围之外）。
- 不实现自定义终端渲染器，终端继续使用 xterm.js（WebView 内渲染）。
- 不做多用户 / 团队同步功能。

## 2. 技术选型

| 层 | 选型 | 理由 |
|---|---|---|
| 壳 / 打包 | **Tauri v2** (2.12.7) | 相比 Electron 体积小一个数量级（~5MB vs ~150MB），原生 Rust 后端，官方活跃维护 |
| 核心 | **Rust 1.90** stable, edition 2021 | 本机已安装；异步 IO 用 Tokio |
| SSH | **russh 0.65** + **russh-sftp 4.0** | 纯 Rust 的 SSH-2 实现，无 C 依赖，跨平台 |
| 凭据存储 | **ring 0.17** | AES-256-GCM 本地加密文件；**不依赖系统钥匙串**（三平台同一套路径、同一套行为） |
| 前端 | **React 18 + TypeScript + Vite 6** | 沿用旧版组件结构，降低移植风险；UI 完全手写 CSS，不引入组件库 |
| 终端 | **xterm.js 5** + fit / web-links / search addon | 成熟的终端模拟器 |
| 状态 | **zustand** | 轻量，避免 Context 重渲染 |
| 字体 | **@fontsource/anton** + **@fontsource/geist-mono** | 自托管，不依赖运行时网络；与 cindy.cn 同源字体 |

**为什么是 Tauri 而不是纯 Rust GUI（egui / iced）：** 纯 Rust GUI 需要自己实现终端渲染（vte 状态机 + 自绘），难以还原 xterm.js 的渲染质量，且 cindy.cn 那种精细排版（字距、裁切角、跑马灯、网格叠层）在 egui 里要付出很大代价。Tauri 让 Rust 承担全部安全敏感与协议相关逻辑，UI 用 CSS 精确还原参考风格，两边都拿到最优解。

## 3. 架构

```
┌──────────────────────────────────────────────────────────┐
│  WebView (React + xterm.js)                              │
│  渲染 / 输入 / 动画 —— 不含任何 SSH 逻辑                  │
└───────────────┬──────────────────────────────────────────┘
                │ invoke(command, args) / listen(event)
┌───────────────▼──────────────────────────────────────────┐
│  Tauri IPC 层 (src-tauri/src/commands/)                   │
│  薄封装：参数校验 → 调用 core → 映射错误 → 返回 serde DTO │
└───────────────┬──────────────────────────────────────────┘
                │
┌───────────────▼──────────────────────────────────────────┐
│  Rust Core                                               │
│  ssh/      client · auth · sftp · osc7 · tracker         │
│  storage/  hosts(无密文) · secrets(门面) · vault(密文)     │
│  state/    SessionManager (会话注册表)                    │
└──────────────────────────────────────────────────────────┘
```

### 模块边界

| 模块 | 职责 | 依赖 |
|---|---|---|
| `ssh/client.rs` | `russh` 连接生命周期、shell channel、窗口尺寸、关闭 | russh |
| `ssh/auth.rs` | 密码 / 私钥 / passphrase 认证，公钥格式解析 | russh-keys, ssh-key |
| `ssh/sftp.rs` | SFTP channel 管理、目录列举、上传下载、删除、mkdir | russh-sftp |
| `ssh/osc7.rs` | OSC 7 序列增量解析器（跨 chunk 状态机） | url |
| `ssh/tracker.rs` | 远程 shell 探测与 cwd 上报钩子注入 | russh |
| `storage/hosts.rs` | 已保存主机读写（**不含任何秘密**） | serde_json, dirs |
| `storage/vault.rs` | 本地加密凭据库（AES-256-GCM） | ring |
| `storage/secrets.rs` | 凭据存取门面（只认 vault 这一种后端） | serde_json |
| `storage/legacy_dir.rs` | 启动期数据目录迁移（包名改过，目录跟着搬） | std |
| `state/sessions.rs` | 会话注册表（id → 会话句柄），并发安全 | tokio, dashmap |
| `commands/*` | IPC 边界，DTO 定义 | core |

每个模块单一职责、互不越界；`commands` 是唯一的跨层入口，保证前端永远拿不到 `russh` 内部类型。

### 关键技术决策

**D1 — 会话 ID 使用 UUIDv7。** 旧版用 `Date.now().toString()`，同毫秒并发连接会撞 ID（缺陷 #12）。`uuid::Uuid::now_v7()` 单调递增且全局唯一。

**D2 — 每个连接一个 SFTP channel，惰性打开并复用。** 旧版每次操作 `conn.sftp()` 新建 channel，且错误路径不 `end()` 导致 channel 泄漏（缺陷 #4、#5）。新实现：连接建立时打开一个 SFTP channel，缓存在会话句柄中，所有文件操作复用它；连接关闭时统一释放。

**D3 — 上传目标路径在 Rust 侧规范化。** 旧版前端传目录路径、后端靠 `endsWith('/')` 判断是否拼文件名，导致子目录上传必然失败（缺陷 #3）。新实现：`sftp_upload` 接收 `remote_dir` + `local_path` 两个独立参数，后端用 `Path::join` 语义拼接目标文件名，杜绝歧义。

**D4 — 传输进度用 transfer_id 关联，而非文件名。** 旧版按文件名匹配进度事件，同名文件并发传输互相覆盖（缺陷 #6）。新实现：每次传输生成唯一 `transfer_id`，前端按 id 更新进度。

**D5 — OSC 7 解析器是跨 chunk 状态机。** 旧版用正则扫 8KB 缓冲区，序列被 chunk 边界切断就永久丢失（缺陷 #10）。新实现：保留一个最多 4KB 的尾部缓冲，识别到不完整的 OSC 序列时保留等待后续 chunk，同时支持 BEL 与 ST 两种终止符。

**D6 — cwd 钩子按 shell 分类注入，且只追加不覆盖。** 旧版无条件写 `export PROMPT_COMMAND=...`，覆盖用户已有配置且在 macOS 默认 zsh 下完全失效（缺陷 #10）。新实现：先执行 `echo $SHELL` 探测 shell，再按类型注入：
- `bash` → 追加到 `PROMPT_COMMAND`：`PROMPT_COMMAND="${PROMPT_COMMAND:+$PROMPT_COMMAND$;}printf ..."`
- `zsh` → 追加到 `precmd_functions` 数组
- `fish` → 包装 `fish_prompt`
- 其他 → 不注入，UI 显示 "cwd 不可用" 而非静默显示错误值

**D6b — 钩子静默注入。** 钩子是写进远端 PTY **输入流**的，终端会把它回显出来：内核 tty 回显一遍，bash 的 readline 启动时又把读到的那行重绘一遍 —— 于是用户每次开 session 都能在终端里看到几行 shell 代码（缺陷 #21）。新实现分三步：
- 申请 PTY 时带上 RFC 4254 的终端模式 `TTY_OP_ECHO = 0`，让服务端把远端 PTY 建好时就是关回显的，注入因此完全不可见；
- 钩子压成**单行**命令，多一行就多打一次提示符；
- 单独一行做收尾：擦掉多出来的提示符（`\033[1A\r\033[J`），并用 `stty echo` 把回显还回去。收尾必须独立成行 —— 钩子那行万一这个 shell 不认，回显也得还回去。

实测（真机 OpenSSH + bash）：钩子代码 0 次出现在终端输出里，提示符只有一行，OSC 7 照常发出，用户输入照常显示。

**D6c — 钩子安装不占用连接关键路径。** 探测 shell 要额外开一个 exec channel（实测约 30ms）。这段放到后台任务里做，连接不等它（缺陷 #22）。

**D7 — 秘密从不落盘明文。** 旧版把密码和 passphrase 明文存 `localStorage`（缺陷 #1）。新实现：`hosts.json` 只存主机元数据，密码 / passphrase 交给凭据后端，条目 key 为 `ssh7://host/<uuid>`。后端不可用时降级为不保存，并在 UI 明确提示，而不是静默明文落盘。后端的选择见 D13。

**D8 — 连接错误完整回传。** 旧版 `catch {}` 吞掉错误，用户只看到"连接失败"（缺陷 #11）。新实现：Rust 侧把错误映射为结构化 `{ code, message, hint }`，前端在标签页和 Toast 中显示具体原因（如"认证失败：密码错误"、"私钥格式无法解析"）。

**D9 — 关闭标签页即断连。** 旧版前端关闭标签不调用 `ssh:disconnect`，SSH 连接持续占用（缺陷 #2）。新实现：会话生命周期由 `SessionManager` 统一管理，标签关闭 → `disconnect` → 释放 SFTP channel 与 shell channel → 从注册表移除。

**D10 — 事件按会话定向，且不依赖全局 window 句柄。** 旧版所有事件用模块级 `mainWindow.webContents.send`，窗口重载后失效（缺陷 #9 关联）。新实现：用 Tauri 的 `AppHandle.emit_to` / 前端 `listen` 精确投递。

**D11 — 删除支持递归。** 旧版目录删除用 `rmdir`，非空目录必然失败（缺陷 #9）。新实现：后端检测到目录非空时递归删除，逐项上报进度。

**D12 — 文件面板随会话切换重新加载。** 旧版 `useEffect` 依赖数组为空，切换会话后仍显示上一个会话的文件（缺陷 #8）。新实现：React key 与状态 store 均以 `sessionId` 为维度，切换即重置并重新列举。

**D13 — 凭据只进本地加密文件，不碰系统钥匙串。** D7 的「只进 OS 钥匙串」在 macOS 上不成立：钥匙串按**程序身份**授权，而未签名（ad-hoc 签名）的应用每升级一次就是新身份，于是每次连接都要弹窗索要「登录」钥匙串密码。路径信任（`security -T`）与放行任意应用（`-A`）都无效 —— 钥匙串只认代码签名，ad-hoc 的 designated requirement 绑的是二进制哈希，重编译即失效。Linux 上没装 Secret Service 时，钥匙串更是压根不可用。

更要命的是**钥匙串是平台专属的**：macOS Keychain / Windows Credential Manager / Linux Secret Service —— 三套 API、三套失败模式（要不要弹窗、条目怎么命名、服务不可用时怎么降级）。一个要同时支持三平台的客户端背着这种差异，只会处处踩坑。

所以凭据存储**只有一种形态**：

- **vault**：应用目录内的 AES-256-GCM 加密文件。`vault.key` 是 32 字节随机主密钥（0600），`vault.bin` 是 `nonce‖密文`（0600），AAD 绑定用途。依赖 `ring 0.17`（russh 已带入，不额外编译）。
- **没有第二种后端**：设置面板里不给选，Rust 侧也没有切换命令，`keyring` 依赖整个删掉 —— 「极简」是产品主张，也不该让用户在两种存放方式之间做选择。
- **各平台行为完全一致**：Windows / Linux / macOS 都是同一份加密文件、同一套代码路径。

代价要说清楚：vault 与「钥匙串 + 放行任意应用」相当，能以当前用户身份运行的进程都能解开；它真正防住的是「明文躺在磁盘上」和「配置文件被同步 / 拷出去」。

**旧用户的钥匙串秘密怎么办？** 早期版本确实用钥匙串存过密码 —— 不能让这些密码直接失效。分两步：

- **在旧版本里搬**（v1.2.2 ~ v1.7.x）：设置面板里切到「本地加密文件」，密码当场搬进加密库、钥匙串里的副本删掉。
- **在中间版本里搬**（v1.8.0 之前发过的迁移版本）：当时的版本自带一次性迁移逻辑，把钥匙串里的密码搬进加密库、钥匙串里的副本同样被删掉。

**v1.8.0 起这两样都不需要了** —— 程序里没有钥匙串代码，自然也没有「等一次授权弹窗」这回事。

**D14 — 连接过程必须有即时反馈。** 旧版点一下主机，要等完整走完 SSH 握手（实测约 350–420ms：握手 92ms、认证 142ms、开 channel 19–116ms）才创建会话，界面这段时间**完全没有反应**，看着像卡住了（缺陷 #22）。新实现：

- 从主机列表点进来时，先摆一个「正在连接」的**占位会话**（标签页立刻出现，显示连接中），连上之后用后端给的真实 session id **原地替换**，标签页不闪；
- 凭据读取实测只要 1–2ms（本地加密库），不是瓶颈；shell 探测与钩子安装移到后台，不占关键路径；
- 失败时占位会话收掉，错误照旧用提示条报给用户。

**D15 — 主机分组用自由文本 + 一份分组清单，不做文件夹树。** 侧边栏里主机按分组归拢。分组名是一个字符串（`SavedHost.group`，可为空），在「连接」对话框里手填。除了主机上的这个字段，`hosts.json` 里另有一份**分组清单**（`groups: Vec<String>`）：

- 清单决定**顺序**与**哪些分组存在**，所以可以先建一个**空分组**（「生产 / 测试 / 本地」），往里放机器时再选 —— 不用等第一台机器保存了分组名才看到那个组；
- 主机上的 `group` 指向清单里的名字；清单里没有、但主机上写着的（老版本留下的）照样显示，追加在清单后面；
- 保存主机时自动把它的分组登记进清单，于是往已有分组里加机器不会打乱顺序；
- 旧版 `hosts.json` 没有 `groups` 字段时按空处理，照样读得出来。

分组本身可以增删改：**新建**（可以空）、**改名**（组里的主机一起改，新名字跟已有分组重名则两组合并）、**删除**（组里的主机回到「未分组」，**主机本身不删**）。界面上：分组标题悬停露出 ✎ 与 🗑，「新建分组」是侧边栏工具栏里的一个按钮（挨着「连接」），点它就地变成输入框。

不做成文件夹（可移动、可嵌套）是因为那要引入树形结构与拖拽进目录，和「只做基本 SSH + 传文件」的定位不符；自由文本分组已经能解决「机器多了分不清」的实际问题。

**D16 — 会话只活在标签栏里，标签支持改名与拖动排序。** 旧版侧边栏有一块 `SESSIONS` 区，和标签栏内容重复 —— 同一个会话在两处出现，改一处另一处不跟着变。新实现把侧边栏让给主机（按 D15 分组），会话只出现在标签栏。

- **改名**：双击标签就地变成输入框（`Enter` 提交 / `Esc` 取消 / 失焦提交），右键菜单里也有「重命名」。改名只改前端会话名，不动主机记录；克隆时把新名字一并传给后端（`session_clone(label)`），克隆出来的会话沿用改名后的名字。
- **排序**：标签按住横向拖动，位移超过 6px 才算拖动（否则算点击），落点用一条红色竖线标出。拖动自己实现的（pointer events），不引入 DnD 库 —— 一个标签栏用不上那套抽象。
- **索引语义**：`move(id, toIndex)` 的 `toIndex` 是**挪动之后的最终下标**（不是「原数组插入位」）。前端计算落点时，跳过被拖动的那个标签、统计指针左侧还剩几个标签，这个数直接就是最终下标 —— 两边语义一致，不用来回换算。早期版本两边语义不一致，导致「往后拖」整体错位一格。

**D17 — 改名期间终端不许抢焦点。** xterm.js 在标签激活后 50ms 会 `focus()` 自己那个隐藏 textarea。双击标签改名会同时切到该标签，于是终端的这次 `focus()` 把改名输入框打死了：用户打的字全跑进远端 shell（缺陷 #23）。新实现把「正在改名」放进 ui store，终端的聚焦 effect 在改名期间不执行；改名结束后该 effect 重新触发，焦点自然交还终端。

**D18 — 侧边栏的三件事：分组可拖动、机器可拖动、单击不连。**

- **分组可拖动排序**：分组标题可以上下拖动，落点用红线标出；新顺序写回 `hosts.json` 的分组清单，下次打开还是这个顺序。未分组那一组固定在最前，不参与排序。
- **机器可拖动换组**：主机行可以拖到任意分组标题上，目标标题亮起红杠，松手即改分组；拖回 `// HOSTS` 就是移出分组。目标分组不存在就顺手建出来。
- **单击不建立连接**：点一下主机只是**选中**（左侧一道红杠），不再直接握手。建连接必须走显式动作 —— 悬停时的 **＋** 或右键菜单里的「开启新会话」；已经开着这台机器的会话时，菜单里另有「切换到已有会话」。

为什么改：单击即连接有两个问题 —— 一是「看一眼主机列表」会莫名开始握手（小半秒，还可能失败弹错），二是想同时开两条连接时没有位置放第二个「开」。把「选中」和「连接」分开之后，这两个意图各有各的入口。

三处拖动都用 pointer events 自己实现，阈值 5px，拖动结束后抑制随之而来的 click。拖动语义与 D16 的标签排序一致：**落点下标就是最终下标**，不做二次换算。

**D19 — 拖动要有手型光标，新建连接默认落在选中分组。**

- **静止即抓手**：分组标题与会话标签的光标是 `grab`，一悬停就告诉用户「这东西能拖」。
- **拖动期间整个窗口都是抓手**：指针一离开被拖元素，CSS 上的光标就失效了，光标会跳回箭头，手感一下就散。所以拖动一开始就把 `document.body` 的光标锁成 `grabbing`、并禁掉选中文字，松手再解锁（`src/lib/drag.ts`）。
- **兜底**：指针在窗口外松开、或者窗口失焦时，浏览器不一定派发 `pointerup`，光标会永远卡在「抓」上。所以拖动期间同时盯着 `pointercancel` 与 `window blur`，任一发生就解锁。
- **默认分组**：新建连接时，「分组」字段已经填好 —— 取当前选中的那台机器所在的分组；没选中（或选中的机器没分组）就是 `HOSTS`（未分组）。字段下面有一行小字说明当前默认值。编辑时带出主机自己的分组，且可以改（清空即移出分组）。
- **表单初值只算一次**：连接对话框挂载时用 `useState` 惰性初始化算出整张表单，之后不再重算；换主机 / 换模式靠 `key` 让组件重新挂载。这样用户在字段里打了一半的字不会被中途冲掉（缺陷 #25）。
- **Esc 关对话框**：和右键菜单、设置面板一个规矩，不用去够右上角的叉。
- **再点一次取消选中**：单击主机是选中，再点同一台就是取消选中（缺陷 #24）。

**D20 — 新建分组在列表里就地建，连接对话框的分组字段排最前。**

- **新建分组不再占用工具栏**：点「＋ 分组」，**分组列表最下面多出一行**，光标已经在里面，输入名字回车才真正建好；`Esc` 取消。原来是在工具栏里把按钮换成输入框，名字得先在别处打好，再"搬运"到列表里 —— 现在"新建"就发生在它最终出现的位置上。
- **命名完成才算数**：提交之前它还不是一个分组 —— 空名字会和「未分组」那个隐式组冲突，所以是"先在列表里占位、命名完成才落进 `hosts.json` 的分组清单"。
- **待编辑的那行不可拖动**：它没有 `data-group`，主机拖过来不会误落进去；行本身也没有拖动语义（不是已建好的分组）。
- **连接对话框把「分组」提到最上面**：分组是这条连接的归属，比名称更结构化，放第一个更符合填写顺序。默认值仍然自动填好（见 D19），焦点仍落在主机地址上 —— 分组不用手输，不该抢焦点。编辑模式同样是第一个字段，两边顺序一致。

**D21 —「仅保存」：只写主机列表，不建连接。**

以前「存下来」只能搭着连接一起发生 —— 勾上「保存」再点「连接」，主机和会话同时落地。这对「先把一整批机器登记进来，之后再连」的场景很别扭：每登记一台都要真的连一次，认证失败还会把整个登记过程打断。

- **独立按钮**：新建时是「仅保存」，编辑时是「保存」。跟「测试连接」「连接」并排，三件事互相独立。
- **id 由后端分配**：前端传空 id 表示「这是台新机器」，Rust 侧生成 UUIDv7（D1 同款）。已有 id 不动 —— 否则「编辑」会变成「新建」。
- **秘密照旧进凭据库**：密码 / 私钥口令走 `host_save` 的同一条路，`hosts.json` 里只留「有没有」的标记，明文一个字都不落盘（缺陷 #1 的性质不变）。新增的单元测试把这条性质钉住。
- **密码留空 = 保持原样，不是清除**：编辑主机时密码框不回显，留空表示「沿用已存的那个」。显式传空串才是清除 —— 前端不传空串，两种语义因此不混淆。
- **复选框的职责收窄**：它现在只管「连接时要不要一并保存」，文案改成「连接时一并保存到主机列表」，不再跟「仅保存」按钮抢同一件事的表述。

Rust 侧把保存逻辑从 Tauri 命令里抽成 `save_host(&HostsStore, &SecretStore, HostSaveRequest)` —— 不依赖 Tauri 运行时，才能在单元测试里直接跑。

**D22 — 所有删除操作都要二次确认。**

一次误点不该换来配置消失。凡是**会丢东西**的操作，点下去都不立刻生效 —— 先弹一个应用自己画的确认框，说清楚「删什么」和「会丢什么」，确认了才动手。

覆盖的入口（一个不落）：

| 操作 | 入口 |
|---|---|
| 删除主机 | 主机行悬停的 ✕、右键「删除」 |
| 删除分组 | 分组标题上的 🗑 |
| 关闭会话 | 标签上的 ×、右键「关闭会话」 |
| 删除远端文件 / 目录 | 文件面板的删除按钮 |
| 恢复默认设置 | 设置面板的「恢复默认」 |

几条约定：

- **确认框由应用自己画**（`ConfirmDialog`），不用浏览器那个 `window.confirm` —— 样式突兀，还会被系统拦在前面。文件面板原来用的就是 `window.confirm`，一并换掉。
- **文案要说清楚后果**，不只是「确定吗？」：删主机说「凭据会一起删掉，无法恢复」，删分组说「机器会回到未分组，机器本身不会被删」，删远端目录说「里面的内容全都会被删」。
- **焦点默认落在确认键上**，回车即确认；`Esc`、点空白、点「取消」都是不执行。
- **危险操作与普通操作分开**：删除类的确认键用 `btn-danger`（红底 + 红光边框），「恢复默认」这种可逆的用普通主按钮。
- **Esc 归上层**：确认框开着时按 `Esc` 只关确认框，底下的连接对话框 / 设置面板不动。为此 ui store 里记了一个 `confirmOpen`，下层对话框的 Esc 处理会先看它。
- **确认框层级最高**（z-index 400），压在连接对话框（100）、通知（200）、右键菜单（300）、设置面板（320）之上。

**D23 — 分组右键就能建连接，默认落在那个分组。**

「这组还差一台机器」是高频动作。从分组标题右键 →「新建连接」，对话框的**分组**字段已经填好这个组，直接填地址就行 —— 不用先去建连接、再手动把分组改过来。

- **右键优先于选中**：分组右键指定的分组，优先于「当前选中主机所在的分组」（D19）。用户明确指了一个组，就听他的。
- **未分组不出菜单**：`// HOSTS` 那一组没有"落在哪个组"的概念，右键它没有菜单；从它新建连接默认就是未分组。
- **右键不折叠**：右键分组标题不会触发折叠 / 展开（左键才触发），也不会启动拖动排序（拖动只认左键）。
- **不串味**：从 A 组右键新建、关掉，再从 B 组右键新建 —— 分组要跟着换。所以对话框的 `key` 里带上了新建时的分组（`new-<分组名>`），换组就重新挂载、重新算初值；工具栏的「＋ 连接」则清掉这个指定，回到"按选中主机算"。

**D24 — 文件面板跟着会话的工作目录走。**

「文件面板」和「终端」是同一台机器的两个视角，却各看各的目录：终端在 `/var/log` 里干活，文件面板还停在 `/`，拖个文件上去就落错地方了。

- **跟随会话目录**：面板打开就落在会话的当前工作目录；终端里 `cd` 之后，面板跟着换路径（跟随依赖 `session://cwd` 事件，见 §7 的 OSC 7 跟踪）。
- **只跟变化，不跟浏览**：跟随的触发条件是**会话目录发生了变化**。用户自己在面板里翻目录不会被拽回去 —— 面板是共享的浏览工具，人也在用它看别处，不能跟人抢。
- **给一个手动入口**：当「正在浏览的目录」≠「会话目录」时，路径栏末尾出现 `>_` 按钮（终端图标），点一下就回到会话目录。这样即便 OSC 7 不可用，用户也有办法回到正轨。
- **明示两个目录**：面板顶部加一行 `// SESSION CWD` 小字，标出**会话目录**；路径框里的则是**正在浏览的目录**。两者不一致时用户一眼能看出来，不会误以为面板显示错了。
- **会话目录未知时不瞎猜**：远端没装 cwd 钩子（不认识的 shell）时 `sessionCwd` 为空，此时面板停在 `/` 且不显示 `// SESSION CWD` 行与跳回按钮 —— 宁可没有，也不要显示一个错的路径。

**D25 — 双击主机：在当前窗口开一个会话标签页。**

双击是「我要连这台机器」的快捷动作。最自然的落点是**当前窗口的标签栏** —— 不是弹出一扇新窗。

- **双击 = 在当前窗口开标签**：这台机器还没开着就新连一个并开成标签；已经开着就**切过去**，不重复开。
- **独立窗口挪到右键菜单**：想「一台机器一扇窗」的仍然可以，右键主机行 →「在新窗口打开」。
- **三种结果**：`session_open_in_window` 返回 `created`（新开了一扇）、`focused`（已经开着，把那扇叫到前面）、`switch`（就在当前窗口里，切标签即可）。前端据此给不同的反馈，不是一句「开好了」。
- **认人靠连接配置，不是地址**：优先按**主机 id** 认人（`id:<hostId>`），没有 id 的临时连接才退回地址三元组（`addr:<host>:<port>:<user>`）。两条配置指向同一台机器，仍然是两台「机器」。
- **多个窗口只挑一个**：开着好几扇时挑一扇叫到前面，不会一次弹出一堆窗。
- **连点两下不会开出两扇窗**：刚开、还在握手的窗口也登记在册（`WindowRegistry`），第二次双击直接聚焦它，而不是因为「还没连上」就再开一扇。
- **参数不走 URL**：新窗口启动时向 Rust 问一次「我是为哪台机器开的」（`window_boot`），而不是从 URL 里解析参数 —— URL 有「参数还没到、前端已经动手了」的竞态。
- **顺带把上一轮遗留的连接断掉**：窗口启动时顺手断开属于这扇窗的旧会话，前端刷新过一次也不会把连接留在后台（缺陷 #2 / #9 在多窗口下的延伸）。

**D26 — 多窗口下事件定向投递，不再广播。**

原来的事件是 `app.emit(...)` —— **广播给所有窗口**。多窗口下这会直接串台：每扇窗都收到别人的终端输出、别人的工作目录、别人的传输进度，界面上是乱的。

- **会话记住自己归谁**：每个 `Session` 记下 `window_label`（它是哪扇窗开的）和 `host_id`（它对应哪条连接配置）。这两个字段是**所有窗口共享的唯一真相** —— 前端每扇窗各有一份 store，跨窗的事实只能记在 Rust 侧。
- **事件只发给归属窗口**：`emit_to(EventTarget::Window { label })` 替代 `emit(...)`，覆盖终端数据、OSC 7 工作目录、连接关闭、传输进度四类事件。
- **监听也必须带窗口标签**（缺陷 #35）：JS 的 `listen()` 默认把监听器注册成 `EventTarget::Any`，而**定向事件匹配不到 `Any`** —— Tauri 的匹配规则是「`Window{label}` 只能命中 `AnyLabel{label}` 或 `Window{label}`」。所以前端监听时必须显式带上本窗口标签（`{ target: label }`），否则事件会被**静默丢弃**：会话显示「已连接」，终端却一个字都收不到，输入也不回显 —— 看起来像没连上服务器。改用 `listenTo()` 统一处理，标签取不到时退回不指定 target。
- **窗口关了，它自己的会话跟着断**：注册在 `Builder::on_window_event` 上（这样运行时新建的窗口也归它管），`Destroyed` 时断开属于该窗口的会话并清掉登记。
- **死会话不算数**：远端断开后会话仍留在注册表里（前端那边还显示着「已断开」的标签），所以给它加一个 `closed` 标记 —— 找「已经开着的会话」时不能把死连接算进去，否则会定位到一扇摆着死连接的窗。
- **mock 要复现这条规则**：`dev-mock.html` 按 target 过滤投递，并提供 `?selftest=1` 自检（发给本窗应当送达、发给别的窗应当收不到）—— 否则这类 bug 在浏览器里根本测不出来。

**D27 — 文件面板宽度可拖动，最多占屏幕一半。**

文件名太长时 `a-very-long-file-name.tar.gz` 被截掉一半，只能靠猜。

- **左边缘一条把手**：往左拖变宽，往右拖变窄；拖动期间光标固定成 `col-resize`，不选文字。
- **上限是屏幕的一半**：再宽终端就没地方放了 —— 「看得全文件名」与「还看得见终端」之间的平衡点。窗口变小时上限跟着变。
- **宽度记住**：存进 `ssh7.settings`（显示偏好，不是凭据），下次打开还是这个宽度。
- **下限 240px**：再窄就看不出是什么了。

**D28 — 传输提示成功即收，失败留下。**

传输进度条只是「知会一声」。传完了还一直挂在屏幕角落，是噪音。

- **成功后 3 秒自动消失**：进度条收掉，不占地方。
- **失败不自动消失**：错误消息得留在屏幕上等用户看完 —— 自动关掉等于把错误藏起来。
- **只收结束的那条**：同时进行的其他传输不受影响。

### cindy.cn 设计语言的六条转译规则

1. **裁切角按钮**：主按钮用 `clip-path` 切掉右上 / 左下角，不用 `border-radius`；次级按钮用四角描边 + 裁切，呼应参考站 `[ ]` 造型。
2. **等宽元数据标签**：所有分区标题写成 `// 01  SAVED HOSTS` 形式——等宽字体、大写、`letter-spacing: .14em`、红色 `//` 前缀。
3. **发丝线 + 网格叠层**：面板之间用 1px `--line` 分隔；欢迎屏铺一层低透明度网格背景。
4. **交叉准星装饰**：`+` 形准星作为四角装饰，透明度 0.15，不抢视线。
5. **巨型水印**：欢迎屏中央 `SSH7` 巨型字（`Anton`，`clamp(6rem, 22vw, 16rem)`），低透明度，做背景层。
6. **跑马灯条**：底部或欢迎屏顶部滚动一条 `◆ SSH7 ◆ SECURE SHELL ◆` 文字带，红色 `--red`，与参考站一致。

### 关键屏幕

- **欢迎屏**：网格背景 + `SSH7` 水印 + 十字准星 + 标签 `— LESS IS MORE` + 白居易《无长物》全诗（衬线 `--font-serif`，四栏排布，每行两联，诗中表示「少」的「窄 / 贫 / 无长物 / 单 / 独」与表示「多」的「皆 / 足」用红色 `.mark` 点出，仿古籍朱点）+ 红色 `新建连接` 裁切角按钮 + 底部跑马灯。页脚 meta 行给出 GitHub 仓库地址（可点，用系统默认浏览器打开）。

> 文案原则：软件做的是极简 —— 只提供基本的 SSH 与传文件，尽量不占资源。界面上不堆技术名词，一句标语嫌多，就让诗自己把主张说出来（诗的上半全是「少」，末联才给「多」）；技术细节留在页脚 meta 行与文档里。
- **侧边栏**：顶部 `// HOSTS` 标签，主机条目左侧 2px 红色选中条（呼应参考站 nav 选中态），悬停浮出编辑 / 删除。
- **标签栏**：等宽小字 + 状态圆点 + 当前目录（等宽、灰、超长省略）。
- **终端区**：xterm 主题对齐令牌，`cursor` 用 `--cream`，选中背景 `--red-wash`。
- **文件面板**：等宽路径输入框、目录在前文件在后、大小右对齐等宽数字。
- **连接对话框**：裁切角红色主按钮「CONNECT」，次级描边「TEST」，测试结果显示延迟毫秒数。

### D29 — 平台专属的能力要加平台门控。

macOS 上能编译过的东西，换个平台就未必能编译过 —— Tauri 把 `title_bar_style` / `hidden_title` 这些「内容延伸到标题栏」的能力标成了 `#[cfg(target_os = "macos")]`，在别的平台上**这两个方法根本不存在**，不是「行为不同」，而是**编译不过**。

- **只在 macOS 上设标题栏样式**：`build_host_window` 里把 macOS 专属的调用放进 `#[cfg(target_os = "macos")]` 分支，其它平台用系统默认标题栏 —— 外观略有差别，但程序能跑。
- **不用 `mut` 改写 builder**：改成重新绑定（`let builder = builder....`），这样在非 macOS 平台上不会留下「声明了 `mut` 却一次都没改过」的警告 —— CI 跑的是 `clippy -- -D warnings`，一条警告就红。
- **CI 必须能跨平台编译**：CI 的 Rust job 跑在 `ubuntu-latest` 上，本地开发机是 macOS —— 这类问题本地永远看不见，只有 CI 能抓到。所以跨平台专属的 API 必须显式门控，而不是靠「我这儿能编过」。

**D30 — 窗口权限要跟着窗口标签的模式一起授权。**

新开的窗口标签是 `host-<uuid>`，不是 `main`。Tauri 的权限是**按窗口标签**匹配的，`capabilities/default.json` 里只写了 `"windows": ["main"]`，新窗口就**一件权限都没有**。

- **权限是编译期写进二进制的**：`capabilities/*.json` 在 `generate_context!()` 时被编进去，源码上看不出来 —— 只有真的在新窗口里连一次服务器才暴露。这是本轮最贵的一个 bug。
- **用 glob 覆盖窗口标签模式**：`"windows": ["main", "host-*"]`。Tauri 内部就是用 `glob::Pattern` 匹配的（官方也支持 `admin-*` 这类写法）。
- **权限自检要跟运行时同语义**：`src-tauri/tests/window_permission.rs` 直接读 capability 的 JSON，用**同一个 glob 库**去匹配窗口标签 —— 自己另写一套匹配逻辑，自检就是自说自话。
- **回归测试必须反向验证过**：把 capability 改回 `["main"]` 时，「新窗口授权」那条测试必须**真的 FAIL**，改回来才重新绿 —— 否则这条测试可能根本没在测那件事。
- **失败必须看得见**：监听注册失败时在终端里直接写出原因（`[终端无法接收远端输出]` + 权限错误），而不是让终端黑着 —— 「连上了却一个字都没有」是最难查的一类症状。
- **产物也要自检**：`src-tauri/tests/asset_probe.rs` 用 `generate_context!()` 取出编译期内嵌的 `dist/assets/index-*.js`，断言它带着关键修复 —— 「源码改了」不等于「打出来的包带着修复」。

**D31 — 别让 webview 接管原生关闭。**

Tauri 的关窗流程有个反直觉的规则：**webview 一旦监听了「关闭请求」，Tauri 就会先取消原生关闭**（`prevent_close`），改由前端接手 —— 前端必须自己再调一次 `destroy()` 才算真关掉。

- **取消与接管是自动的**：`WindowEvent::CloseRequested` 里，只要这个窗口有 `tauri://close-requested` 的 JS 监听器，Tauri 就 `prevent_close()`，然后把事件发给 webview。
- **`destroy()` 要过权限**：`core:window:default` 里**只有只读查询**（`allow-title`、`allow-is-focused` 之类），**没有** `allow-destroy` / `allow-close`。权限被拒 → 关闭流程走到一半断了 → 窗口永远关不掉，点红点没反应。
- **所以前端不注册 `onCloseRequested`**：关窗的清理（断开这扇窗的所有 SSH 会话）放在 Rust 侧的 `Destroyed` 事件里回收 —— 不依赖前端还活着（它马上就要死了）。原生关闭就保持原生：红点一点，窗口就关。
- **顺手把权限补上**：`core:window:allow-destroy` 显式授予。万一以后又有代码注册了关闭监听，接管这条路至少走得通（纵深防御），不会再出现「关不掉」。
- **这类 bug 要看得见**：诊断时在 Rust 的 `on_window_event` 里临时打一行日志，确认「原生关闭请求确实到达了 Tauri」—— 这一句日志就把「点击没送到」和「到了但被取消」区分开了，不用瞎猜。
- **回归测试钉住两件事**：`window_permission.rs` 里断言 capability 给了 `allow-destroy`，并断言 `src/App.tsx` 里**没有**真的调用 `.onCloseRequested(`（注释里提到不算）。两条都做过反向验证：改回坏状态，测试必须真的红。

**D32 — 外链要「命令权限 + scope」两层，缺一不可。**

Tauri 的 opener 插件把权限拆成两层：`opener:allow-open-url` 允许**调用** `open_url` 命令；`opener:allow-default-urls` 才是**允许哪些 URL**（scope：`mailto:` / `tel:` / `http://` / `https://`）。只给前者，命令调得起来，URL 却被 scope 检查拒掉。

- **失败是静默的**：前端 catch 之后退化成 `window.open` —— 而在 Tauri 的 webview 里那**没有新窗口、也没有报错**，用户只看到「点了图标毫无动静」。
- **所以异常要往上抛**：调用方（设置面板）把失败显示成提示条，而不是把链接变成死的。
- **回归测试读真实数据**：`tests/external_links.rs` 读 capability 与生成的 ACL 清单，断言两层权限都在、scope 里含 `https://*`、并且前端写死的仓库地址落在 scope 内 —— 还做了反向验证：去掉 scope 权限，测试必须真的红。
- **权限是编译期写进二进制的**：源码上完全看不出来，只有点一下才知道 —— 这类「点了没反应」的问题必须靠测试钉住。

**D33 — 包名统一了，数据目录也得跟着搬。**

GitHub 账号从 `alishiguang` 改成 `chuaker7`，SSH7 的包名（`identifier`）也就跟着统一成 `com.chuaker7.ssh7`。但 Tauri 的应用配置目录是 `dirs::config_dir()/<identifier>` —— **包名一变，数据目录就换一个**。用户升级后会发现主机列表和凭据库「凭空消失」（其实还躺在旧目录里）。

- **旧包名不止一个**：SSH7 早期开发阶段用过 `com.igigi.ssh7`，之后是 `com.alishiguang.ssh7`。迁移清单按「从新到旧」排列，多个旧目录同时存在时认领**数据更全的那一个**。
- **整个目录搬，不逐个文件拷**：凭据库是 `vault.bin`（密文）+ `vault.key`（密钥）**一对**文件，密钥对得上才解得开。拆开搬、或者把新旧目录合并，都会把库搞成「密文在、密钥不配对」的坏状态 —— 那比「找不到文件」还难排查。
- **多个旧目录不合并**：早期目录里的主机记录和现在的**主机 id 不同**，合并会变成同一台机器在列表里出现两行，其中一行还没密码 —— 比不合并更糟。没被认领的旧目录原样留着，应用压根不读它。
- **新目录已经有数据就不动**：新标识符的版本一旦存过东西，旧目录一律不碰 —— 覆盖会丢数据。
- **macOS 侧的目录也得统一**：`~/Library/WebKit/<包名>`（界面偏好存在这儿）、`~/Library/Caches/<包名>`、`~/Library/Preferences/<包名>.plist` 都是按包名落的盘 —— 这些目录 macOS 自己管，应用代码管不着，得手工改名统一。
- **回归测试钉住行为**：`storage/legacy_dir.rs` 的单测覆盖「搬」「新目录有数据就跳过」「没有旧目录就啥也不干」「幂等」「凭据库那一对文件不拆散」，并且做过反向验证 —— 把迁移改成空操作，5 条测试必须真的红。

**D34 — 发布前要查产物，但不能用「在二进制里搜字符串」这种查法。**

Tauri 的权限是**编译期写进二进制**的，源码上看不出来 —— 所以「源码改了」不等于「包里带着修复」，发布前确实要查产物。但**怎么查**是个坑：

- **不能用字节查找去二进制里搜权限名**。链接器会**拆分字符串**、还会做**后缀合并**（`com.chuaker7.ssh7` 和 `com.alishiguang.ssh7` 共用 `ssh7` 这条尾巴）。于是同一个串在 arm64 里是连续的、在 x64 里就断成了 `com.chua` + 碎片。
- **假警报比漏报更糟**：x64 的包**一直是好的**（运行时探针一跑，它建的数据目录就是 `com.chuaker7.ssh7`），脚本却报它「缺 `allow-default-urls`、缺 `allow-destroy`」。查了半天，最后发现是查法错了。
- **可靠的做法是运行时探针**：拿一个临时 `HOME` 跑产物，看它**实际建出哪个数据目录** —— 这直接读的就是二进制内嵌的标识符，跑出来什么就是什么，不受链接布局影响。
- **权限则用 codegen 自检**：权限来自 `capabilities/*.json` 与插件的权限清单，**与目标架构无关**（只有 capability schema 的生成是按目标走的）。所以逐目标跑一遍 `cargo test --release --target <triple>`（含读内嵌上下文的那几条）就够了。
- **依赖图是另一道防线**：`cargo tree` 里没有 `keyring`、源码里没有 `credential_store` —— 这两样不依赖字符串布局，查得死。
- **CI 也要查**：流水线用了 `rust-cache`，缓存里可能带着旧的构建产物；自检不能只在本机做。

`scripts/check-artifacts.sh` 现在做三件事：运行时探针（标识符）、依赖图与源码检查（没有钥匙串残留）、逐目标编译期自检（权限）。CI 和发布流水线都接上了。

**D35 — 一件事只在一处说。**

传输进度提示在**终端区右下角**和**文件面板底部**各渲染了一份，两边订阅的是同一个 store、只按 `sessionId` 过滤 —— 于是同一次下载/上传在两边各出现一条一模一样的进度条。下载完成还额外弹一条「下载完成」提示条，第三遍。

- **给每次传输记一个「从哪儿发起」**（`origin: 'panel' | 'terminal'`），进度提示**只显示在发起它的那一侧**：文件面板里发起的（下载按钮、面板里的上传/拖放）显示在面板底部；拖到终端的上传显示在终端右下角。
- **「谁显示什么」只定义一次**：`transfersFor(transfers, sessionId, origin)`。两边各调各的，免得各写一套过滤规则、又写出两套不一样的来。
- **不是为了少显示而少显示**：终端发起的上传，终端里仍留一行 `✓ 上传完成 <文件> → <目录>` —— 那是**回滚历史里的传输记录**，和浮在屏幕上的进度条不是一回事。
- **成功不再另弹提示条**：进度卡已经说了「完成」，再弹一条 toast 就是同一件事说第三遍。**失败仍然弹** —— 错误必须显眼。
- **回归测试钉住**：store 单测断言「面板发起的只在面板、终端发起的只在终端、别的会话的不显示」。

## 7. 数据流

**连接建立**
```
用户点 CONNECT
  → 前端 session_connect(ConnectRequest)
  → Rust: 从凭据库取密文 → 构造 russh client → connect()
  → 认证成功 → 打开 shell channel（term=xterm-256color, 80x24 初值）
  → 打开 SFTP channel（复用）
  → 探测 $SHELL → 注入 cwd 上报钩子
  → 注册会话到 SessionManager → 返回 SessionInfo
  → 前端创建 xterm 实例，绑定 session://data / closed / cwd
```

**终端输入**
```
键盘 → xterm onData → session_write(session_id, data)
  → Rust → shell channel.write(data)
```

**远端输出**
```
shell channel 读 → Rust 任务 → 增量喂入 OSC7 解析器
  → 解析出 cwd 则 emit session://cwd
  → 原始字节 emit session://data → 前端 xterm.write()
```

**文件上传**
```
用户拖文件 → 前端读本地路径 → sftp_upload(session_id, local_path, remote_dir)
  → Rust: SFTP channel.write_file(remote_dir/basename) ，流式读本地文件
  → 每块 emit transfer://progress { transfer_id, transferred, total }
  → 完成后前端刷新目录（清缓存）
```

**错误**
```
任何 Rust 错误 → AppError { code, message, hint }
  → Tauri invoke 返回 Err(序列化后的 AppError)
  → 前端 bridge 统一转成 Error 对象 → Toast 展示 + 标签页状态更新
```

---

## 8. 错误处理策略

| 类别 | 策略 |
|---|---|
| 网络 / 超时 | Rust 侧统一 15s `tokio::time::timeout`，返回 `{ code: "TIMEOUT", message }`；前端显示"连接超时"，保留重试入口 |
| 认证失败 | 返回 `{ code: "AUTH_FAILED", hint: "检查用户名或密码 / 私钥口令" }` |
| 私钥解析失败 | 返回 `{ code: "KEY_INVALID", message: <解析器原文> }`，不打印私钥内容 |
| 远端路径不存在 | 返回 `{ code: "NO_SUCH_PATH" }`，文件面板保留当前路径并提示 |
| 传输中断 | 传输任务标记 `failed`，保留已传输字节数，允许重试 |
| 凭据库不可写 | 降级为"本次会话有效，不持久化"，UI 明确提示，绝不静默明文落盘 |
| 凭据库主密钥丢失 / 被替换 | 返回 `{ code: "INTERNAL", hint: "凭据库解密失败" }`，提示用户删除凭据库后重新保存密码 |
| 窗体关闭 | 前端 `beforeunload` 触发全量 `disconnect` |

所有错误在 Rust 侧统一经 `AppError` 枚举产出，禁止把 `anyhow` 的裸字符串直接抛给前端。

## 9. 测试策略

| 层 | 手段 | 覆盖 |
|---|---|---|
| Rust 单元 | `cargo test` | OSC7 解析器（分块 / BEL / ST / 截断）、路径拼接、错误映射、传输百分比夹取、shell 钩子脚本生成 |
| Rust 集成 | `russh` 本地 in-process server | 认证成功 / 失败、SFTP 列举与读写、channel 复用与释放计数 |
| 前端 | Vitest | store reducer、bridge DTO 映射、文件面板路径拼接 |
| 端到端 | 手工 + `tauri dev` | 连接真实主机、拖拽上传、切换会话、关闭标签后确认 SSH 连接被释放（`ss -tnp` 观察） |
| 构建 | `cargo tauri build` | macOS / Windows / Linux 产物 |

**连接释放验证**是本次重写的关键验收项：用 `lsof -i :22` 或服务端 `ss` 确认关闭标签后 socket 真正消失，而不只是 UI 移除。

## 12. 验收标准

1. `cargo test` 全绿；`cargo clippy` 无警告；`npm run build` 无类型错误。
2. 多会话终端可用，标签切换不串数据；切换会话时终端内容各自独立保留。
3. SFTP 文件面板可列举 / 上传 / 下载 / 删除（含非空目录递归）/ 新建目录。
4. 拖拽文件到终端区与文件面板均可上传，且在任意子目录均成功。
5. 关闭标签页后，服务端确认 SSH 连接已释放。
6. 已保存主机的密码不出现在 `hosts.json` 或任何明文文件中。
7. 连接失败时界面显示具体原因与修复提示。
8. 界面通过 §5 的六条转译规则，视觉参考 cindy.cn。
9. `chuaker7/SSH7` 仓库公开可见，README 与 LICENSE 完整。
