# SSH7 — 设计规格

> 用 Rust 重写 SSH 客户端 LuciSSHClient，视觉语言参考 cindy.cn。
> 状态：待评审 · 日期：2026-11-24 · 上游项目：LuciSSHClient（Electron + React + ssh2）

---

## 1. 目标与非目标

### 目标

1. **核心逻辑全部 Rust 重写**：SSH 握手与会话、SFTP 文件操作、密钥与密码存储、目录跟踪，全部由 Rust 实现，前端只负责渲染与输入转发。
2. **视觉重新设计**：采用 cindy.cn 的设计语言（Ink 黑 / Cream 米白 / 信号红），不是把旧样式换色。
3. **功能与旧版对齐**：多会话终端、SFTP 文件管理、拖拽上传 / 下载、保存主机、连通性测试。
4. **修掉旧版全部已知缺陷**：见 §6 缺陷清单。
5. **开源发布**：GitHub 公开仓库 `alishiguang/SSH7`，MIT 协议。

### 非目标

- 不做端口转发、会话录制、批量分发（本轮范围之外）。
- 不实现自定义终端渲染器，终端继续使用 xterm.js（WebView 内渲染）。
- 不做多用户 / 团队同步功能。

## 2. 技术选型

| 层 | 选型 | 理由 |
|---|---|---|
| 壳 / 打包 | **Tauri v2** (2.12.7) | 相比 Electron 体积小一个数量级（~5MB vs ~150MB），原生 Rust 后端，官方活跃维护 |
| 核心 | **Rust 1.90** stable, edition 2021 | 本机已安装；异步 IO 用 Tokio |
| SSH | **russh 0.65** + **russh-sftp 4.0** | 纯 Rust 的 SSH-2 实现，无 C 依赖，跨平台 |
| 密钥存储 | **keyring 4.2** + **ring 0.17** | macOS Keychain / Windows Credential Manager / Linux Secret Service；本地加密凭据库用 AES-256-GCM |
| 前端 | **React 18 + TypeScript + Vite 6** | 沿用旧版组件结构，降低移植风险；UI 完全手写 CSS，不引入组件库 |
| 终端 | **xterm.js 5** + fit / web-links / search addon | 成熟的终端模拟器 |
| 状态 | **zustand** | 轻量，避免 Context 重渲染 |
| 字体 | **@fontsource/anton** + **@fontsource/geist-mono** | 自托管，不依赖运行时网络；与 cindy.cn 同源字体 |

**为什么是 Tauri 而不是纯 Rust GUI（egui / iced）：** 纯 Rust GUI 需要自己实现终端渲染（vte 状态机 + 自绘），难以还原 xterm.js 的渲染质量，且 cindy.cn 那种精细排版（字距、裁切角、跑马灯、网格叠层）在 egui 里要付出很大代价。Tauri 让 Rust 承担全部安全敏感与协议相关逻辑，UI 用 CSS 精确还原参考风格，两边都拿到最优解。

## 3. 架构

```
┌──────────────────────────────────────────────────────────┐
│  WebView (React + xterm.js)                              │
│  渲染 / 输入 / 动画 —— 不含任何 SSH 逻辑                  │
└───────────────┬──────────────────────────────────────────┘
                │ invoke(command, args) / listen(event)
┌───────────────▼──────────────────────────────────────────┐
│  Tauri IPC 层 (src-tauri/src/commands/)                   │
│  薄封装：参数校验 → 调用 core → 映射错误 → 返回 serde DTO │
└───────────────┬──────────────────────────────────────────┘
                │
┌───────────────▼──────────────────────────────────────────┐
│  Rust Core                                               │
│  ssh/      client · auth · sftp · osc7 · tracker         │
│  storage/  hosts(无密文) · secrets(门面) · vault/keyring(密文)│
│  state/    SessionManager (会话注册表)                    │
└──────────────────────────────────────────────────────────┘
```

### 模块边界

| 模块 | 职责 | 依赖 |
|---|---|---|
| `ssh/client.rs` | `russh` 连接生命周期、shell channel、窗口尺寸、关闭 | russh |
| `ssh/auth.rs` | 密码 / 私钥 / passphrase 认证，公钥格式解析 | russh-keys, keyring |
| `ssh/sftp.rs` | SFTP channel 管理、目录列举、上传下载、删除、mkdir | russh-sftp |
| `ssh/osc7.rs` | OSC 7 序列增量解析器（跨 chunk 状态机） | url |
| `ssh/tracker.rs` | 远程 shell 探测与 cwd 上报钩子注入 | russh |
| `storage/hosts.rs` | 已保存主机读写（**不含任何秘密**） | serde_json, dirs |
| `storage/keyring.rs` | 密码 / passphrase 存取，OS 钥匙串 | keyring |
| `storage/secrets.rs` | 凭据后端门面（vault / keyring 分派 + 迁移） | serde_json |
| `storage/vault.rs` | 本地加密凭据库（AES-256-GCM） | ring |
| `state/sessions.rs` | 会话注册表（id → 会话句柄），并发安全 | tokio, dashmap |
| `commands/*` | IPC 边界，DTO 定义 | core |

每个模块单一职责、互不越界；`commands` 是唯一的跨层入口，保证前端永远拿不到 `russh` 内部类型。

### 关键技术决策

**D1 — 会话 ID 使用 UUIDv7。** 旧版用 `Date.now().toString()`，同毫秒并发连接会撞 ID（缺陷 #12）。`uuid::Uuid::now_v7()` 单调递增且全局唯一。

**D2 — 每个连接一个 SFTP channel，惰性打开并复用。** 旧版每次操作 `conn.sftp()` 新建 channel，且错误路径不 `end()` 导致 channel 泄漏（缺陷 #4、#5）。新实现：连接建立时打开一个 SFTP channel，缓存在会话句柄中，所有文件操作复用它；连接关闭时统一释放。

**D3 — 上传目标路径在 Rust 侧规范化。** 旧版前端传目录路径、后端靠 `endsWith('/')` 判断是否拼文件名，导致子目录上传必然失败（缺陷 #3）。新实现：`sftp_upload` 接收 `remote_dir` + `local_path` 两个独立参数，后端用 `Path::join` 语义拼接目标文件名，杜绝歧义。

**D4 — 传输进度用 transfer_id 关联，而非文件名。** 旧版按文件名匹配进度事件，同名文件并发传输互相覆盖（缺陷 #6）。新实现：每次传输生成唯一 `transfer_id`，前端按 id 更新进度。

**D5 — OSC 7 解析器是跨 chunk 状态机。** 旧版用正则扫 8KB 缓冲区，序列被 chunk 边界切断就永久丢失（缺陷 #10）。新实现：保留一个最多 4KB 的尾部缓冲，识别到不完整的 OSC 序列时保留等待后续 chunk，同时支持 BEL 与 ST 两种终止符。

**D6 — cwd 钩子按 shell 分类注入，且只追加不覆盖。** 旧版无条件写 `export PROMPT_COMMAND=...`，覆盖用户已有配置且在 macOS 默认 zsh 下完全失效（缺陷 #10）。新实现：先执行 `echo $SHELL` 探测 shell，再按类型注入：
- `bash` → 追加到 `PROMPT_COMMAND`：`PROMPT_COMMAND="${PROMPT_COMMAND:+$PROMPT_COMMAND$;}printf ..."`
- `zsh` → 追加到 `precmd_functions` 数组
- `fish` → 包装 `fish_prompt`
- 其他 → 不注入，UI 显示 "cwd 不可用" 而非静默显示错误值

**D6b — 钩子静默注入。** 钩子是写进远端 PTY **输入流**的，终端会把它回显出来：内核 tty 回显一遍，bash 的 readline 启动时又把读到的那行重绘一遍 —— 于是用户每次开 session 都能在终端里看到几行 shell 代码（缺陷 #21）。新实现分三步：
- 申请 PTY 时带上 RFC 4254 的终端模式 `TTY_OP_ECHO = 0`，让服务端把远端 PTY 建好时就是关回显的，注入因此完全不可见；
- 钩子压成**单行**命令，多一行就多打一次提示符；
- 单独一行做收尾：擦掉多出来的提示符（`\033[1A\r\033[J`），并用 `stty echo` 把回显还回去。收尾必须独立成行 —— 钩子那行万一这个 shell 不认，回显也得还回去。

实测（真机 OpenSSH + bash）：钩子代码 0 次出现在终端输出里，提示符只有一行，OSC 7 照常发出，用户输入照常显示。

**D6c — 钩子安装不占用连接关键路径。** 探测 shell 要额外开一个 exec channel（实测约 30ms）。这段放到后台任务里做，连接不等它（缺陷 #22）。

**D7 — 秘密从不落盘明文。** 旧版把密码和 passphrase 明文存 `localStorage`（缺陷 #1）。新实现：`hosts.json` 只存主机元数据，密码 / passphrase 交给凭据后端，条目 key 为 `ssh7://host/<uuid>`。后端不可用时降级为不保存，并在 UI 明确提示，而不是静默明文落盘。后端的选择见 D13。

**D8 — 连接错误完整回传。** 旧版 `catch {}` 吞掉错误，用户只看到"连接失败"（缺陷 #11）。新实现：Rust 侧把错误映射为结构化 `{ code, message, hint }`，前端在标签页和 Toast 中显示具体原因（如"认证失败：密码错误"、"私钥格式无法解析"）。

**D9 — 关闭标签页即断连。** 旧版前端关闭标签不调用 `ssh:disconnect`，SSH 连接持续占用（缺陷 #2）。新实现：会话生命周期由 `SessionManager` 统一管理，标签关闭 → `disconnect` → 释放 SFTP channel 与 shell channel → 从注册表移除。

**D10 — 事件按会话定向，且不依赖全局 window 句柄。** 旧版所有事件用模块级 `mainWindow.webContents.send`，窗口重载后失效（缺陷 #9 关联）。新实现：用 Tauri 的 `AppHandle.emit_to` / 前端 `listen` 精确投递。

**D11 — 删除支持递归。** 旧版目录删除用 `rmdir`，非空目录必然失败（缺陷 #9）。新实现：后端检测到目录非空时递归删除，逐项上报进度。

**D12 — 文件面板随会话切换重新加载。** 旧版 `useEffect` 依赖数组为空，切换会话后仍显示上一个会话的文件（缺陷 #8）。新实现：React key 与状态 store 均以 `sessionId` 为维度，切换即重置并重新列举。

**D13 — 凭据存储后端可切换，macOS 默认用本地加密文件。** D7 的「只进 OS 钥匙串」在 macOS 上不成立：钥匙串按**程序身份**授权，而未签名（ad-hoc 签名）的应用每升级一次就是新身份，于是每次连接都要弹窗索要「登录」钥匙串密码。路径信任（`security -T`）与放行任意应用（`-A`）都无效 —— 钥匙串只认代码签名，ad-hoc 的 designated requirement 绑的是二进制哈希，重编译即失效。

因此把凭据存储抽象成两个后端，由 `SecretStore` 门面按偏好分派：

- **vault**（macOS 默认）：应用目录内的 AES-256-GCM 加密文件。`vault.key` 是 32 字节随机主密钥（0600），`vault.bin` 是 `nonce‖密文`（0600），AAD 绑定用途。依赖 `ring 0.17`（russh 已带入，不额外编译）。
- **keyring**（Windows / Linux 上钥匙串可用时默认）：系统钥匙串 / 凭据管理器 / Secret Service。钥匙串不可用时（Linux 上没装 Secret Service）自动退回 vault —— 否则「保存一台带密码的主机」会直接失败，用户什么都存不了。

读取时的兜底查找是**容错**的：另一个后端读不出来（钥匙串不可用 / 用户没点「允许」）一律按「没有这条秘密」处理，不能让用户选了当前后端却被另一个后端连累。

切换后端时按 hosts 列表把已有条目搬过去；读取时若当前后端没有，去另一个后端兜底找一次并顺手搬回 —— 所以从钥匙串切到 vault 后**只有第一次**需要授权。偏好本身不是秘密，明文存在 `credential-store.json`。

威胁模型要说清楚：vault 与「钥匙串 + 放行任意应用」相当，能以当前用户身份运行的进程都能解开；它真正防住的是「明文躺在磁盘上」和「配置文件被同步 / 拷出去」。

**D14 — 连接过程必须有即时反馈。** 旧版点一下主机，要等完整走完 SSH 握手（实测约 350–420ms：握手 92ms、认证 142ms、开 channel 19–116ms）才创建会话，界面这段时间**完全没有反应**，看着像卡住了（缺陷 #22）。新实现：

- 从主机列表点进来时，先摆一个「正在连接」的**占位会话**（标签页立刻出现，显示连接中），连上之后用后端给的真实 session id **原地替换**，标签页不闪；
- 凭据读取实测只要 1–2ms（本地加密库），不是瓶颈；shell 探测与钩子安装移到后台，不占关键路径；
- 失败时占位会话收掉，错误照旧用提示条报给用户。

**D15 — 主机分组用自由文本 + 一份分组清单，不做文件夹树。** 侧边栏里主机按分组归拢。分组名是一个字符串（`SavedHost.group`，可为空），在「连接」对话框里手填。除了主机上的这个字段，`hosts.json` 里另有一份**分组清单**（`groups: Vec<String>`）：

- 清单决定**顺序**与**哪些分组存在**，所以可以先建一个**空分组**（「生产 / 测试 / 本地」），往里放机器时再选 —— 不用等第一台机器保存了分组名才看到那个组；
- 主机上的 `group` 指向清单里的名字；清单里没有、但主机上写着的（老版本留下的）照样显示，追加在清单后面；
- 保存主机时自动把它的分组登记进清单，于是往已有分组里加机器不会打乱顺序；
- 旧版 `hosts.json` 没有 `groups` 字段时按空处理，照样读得出来。

分组本身可以增删改：**新建**（可以空）、**改名**（组里的主机一起改，新名字跟已有分组重名则两组合并）、**删除**（组里的主机回到「未分组」，**主机本身不删**）。界面上：分组标题悬停露出 ✎ 与 🗑，「新建分组」是侧边栏工具栏里的一个按钮（挨着「连接」），点它就地变成输入框。

不做成文件夹（可移动、可嵌套）是因为那要引入树形结构与拖拽进目录，和「只做基本 SSH + 传文件」的定位不符；自由文本分组已经能解决「机器多了分不清」的实际问题。

**D16 — 会话只活在标签栏里，标签支持改名与拖动排序。** 旧版侧边栏有一块 `SESSIONS` 区，和标签栏内容重复 —— 同一个会话在两处出现，改一处另一处不跟着变。新实现把侧边栏让给主机（按 D15 分组），会话只出现在标签栏。

- **改名**：双击标签就地变成输入框（`Enter` 提交 / `Esc` 取消 / 失焦提交），右键菜单里也有「重命名」。改名只改前端会话名，不动主机记录；克隆时把新名字一并传给后端（`session_clone(label)`），克隆出来的会话沿用改名后的名字。
- **排序**：标签按住横向拖动，位移超过 6px 才算拖动（否则算点击），落点用一条红色竖线标出。拖动自己实现的（pointer events），不引入 DnD 库 —— 一个标签栏用不上那套抽象。
- **索引语义**：`move(id, toIndex)` 的 `toIndex` 是**挪动之后的最终下标**（不是「原数组插入位」）。前端计算落点时，跳过被拖动的那个标签、统计指针左侧还剩几个标签，这个数直接就是最终下标 —— 两边语义一致，不用来回换算。早期版本两边语义不一致，导致「往后拖」整体错位一格。

**D17 — 改名期间终端不许抢焦点。** xterm.js 在标签激活后 50ms 会 `focus()` 自己那个隐藏 textarea。双击标签改名会同时切到该标签，于是终端的这次 `focus()` 把改名输入框打死了：用户打的字全跑进远端 shell（缺陷 #23）。新实现把「正在改名」放进 ui store，终端的聚焦 effect 在改名期间不执行；改名结束后该 effect 重新触发，焦点自然交还终端。

**D18 — 侧边栏的三件事：分组可拖动、机器可拖动、单击不连。**

- **分组可拖动排序**：分组标题可以上下拖动，落点用红线标出；新顺序写回 `hosts.json` 的分组清单，下次打开还是这个顺序。未分组那一组固定在最前，不参与排序。
- **机器可拖动换组**：主机行可以拖到任意分组标题上，目标标题亮起红杠，松手即改分组；拖回 `// HOSTS` 就是移出分组。目标分组不存在就顺手建出来。
- **单击不建立连接**：点一下主机只是**选中**（左侧一道红杠），不再直接握手。建连接必须走显式动作 —— 悬停时的 **＋** 或右键菜单里的「开启新会话」；已经开着这台机器的会话时，菜单里另有「切换到已有会话」。

为什么改：单击即连接有两个问题 —— 一是「看一眼主机列表」会莫名开始握手（小半秒，还可能失败弹错），二是想同时开两条连接时没有位置放第二个「开」。把「选中」和「连接」分开之后，这两个意图各有各的入口。

三处拖动都用 pointer events 自己实现，阈值 5px，拖动结束后抑制随之而来的 click。拖动语义与 D16 的标签排序一致：**落点下标就是最终下标**，不做二次换算。

**D19 — 拖动要有手型光标，新建连接默认落在选中分组。**

- **静止即抓手**：分组标题与会话标签的光标是 `grab`，一悬停就告诉用户「这东西能拖」。
- **拖动期间整个窗口都是抓手**：指针一离开被拖元素，CSS 上的光标就失效了，光标会跳回箭头，手感一下就散。所以拖动一开始就把 `document.body` 的光标锁成 `grabbing`、并禁掉选中文字，松手再解锁（`src/lib/drag.ts`）。
- **兜底**：指针在窗口外松开、或者窗口失焦时，浏览器不一定派发 `pointerup`，光标会永远卡在「抓」上。所以拖动期间同时盯着 `pointercancel` 与 `window blur`，任一发生就解锁。
- **默认分组**：新建连接时，「分组」字段已经填好 —— 取当前选中的那台机器所在的分组；没选中（或选中的机器没分组）就是 `HOSTS`（未分组）。字段下面有一行小字说明当前默认值。编辑时带出主机自己的分组，且可以改（清空即移出分组）。
- **表单初值只算一次**：连接对话框挂载时用 `useState` 惰性初始化算出整张表单，之后不再重算；换主机 / 换模式靠 `key` 让组件重新挂载。这样用户在字段里打了一半的字不会被中途冲掉（缺陷 #25）。
- **Esc 关对话框**：和右键菜单、设置面板一个规矩，不用去够右上角的叉。
- **再点一次取消选中**：单击主机是选中，再点同一台就是取消选中（缺陷 #24）。

**D20 — 新建分组在列表里就地建，连接对话框的分组字段排最前。**

- **新建分组不再占用工具栏**：点「＋ 分组」，**分组列表最下面多出一行**，光标已经在里面，输入名字回车才真正建好；`Esc` 取消。原来是在工具栏里把按钮换成输入框，名字得先在别处打好，再"搬运"到列表里 —— 现在"新建"就发生在它最终出现的位置上。
- **命名完成才算数**：提交之前它还不是一个分组 —— 空名字会和「未分组」那个隐式组冲突，所以是"先在列表里占位、命名完成才落进 `hosts.json` 的分组清单"。
- **待编辑的那行不可拖动**：它没有 `data-group`，主机拖过来不会误落进去；行本身也没有拖动语义（不是已建好的分组）。
- **连接对话框把「分组」提到最上面**：分组是这条连接的归属，比名称更结构化，放第一个更符合填写顺序。默认值仍然自动填好（见 D19），焦点仍落在主机地址上 —— 分组不用手输，不该抢焦点。编辑模式同样是第一个字段，两边顺序一致。

**D21 —「仅保存」：只写主机列表，不建连接。**

以前「存下来」只能搭着连接一起发生 —— 勾上「保存」再点「连接」，主机和会话同时落地。这对「先把一整批机器登记进来，之后再连」的场景很别扭：每登记一台都要真的连一次，认证失败还会把整个登记过程打断。

- **独立按钮**：新建时是「仅保存」，编辑时是「保存」。跟「测试连接」「连接」并排，三件事互相独立。
- **id 由后端分配**：前端传空 id 表示「这是台新机器」，Rust 侧生成 UUIDv7（D1 同款）。已有 id 不动 —— 否则「编辑」会变成「新建」。
- **秘密照旧进凭据库**：密码 / 私钥口令走 `host_save` 的同一条路，`hosts.json` 里只留「有没有」的标记，明文一个字都不落盘（缺陷 #1 的性质不变）。新增的单元测试把这条性质钉住。
- **密码留空 = 保持原样，不是清除**：编辑主机时密码框不回显，留空表示「沿用已存的那个」。显式传空串才是清除 —— 前端不传空串，两种语义因此不混淆。
- **复选框的职责收窄**：它现在只管「连接时要不要一并保存」，文案改成「连接时一并保存到主机列表」，不再跟「仅保存」按钮抢同一件事的表述。

Rust 侧把保存逻辑从 Tauri 命令里抽成 `save_host(&HostsStore, &SecretStore, HostSaveRequest)` —— 不依赖 Tauri 运行时，才能在单元测试里直接跑。

**D22 — 所有删除操作都要二次确认。**

一次误点不该换来配置消失。凡是**会丢东西**的操作，点下去都不立刻生效 —— 先弹一个应用自己画的确认框，说清楚「删什么」和「会丢什么」，确认了才动手。

覆盖的入口（一个不落）：

| 操作 | 入口 |
|---|---|
| 删除主机 | 主机行悬停的 ✕、右键「删除」 |
| 删除分组 | 分组标题上的 🗑 |
| 关闭会话 | 标签上的 ×、右键「关闭会话」 |
| 删除远端文件 / 目录 | 文件面板的删除按钮 |
| 恢复默认设置 | 设置面板的「恢复默认」 |

几条约定：

- **确认框由应用自己画**（`ConfirmDialog`），不用浏览器那个 `window.confirm` —— 样式突兀，还会被系统拦在前面。文件面板原来用的就是 `window.confirm`，一并换掉。
- **文案要说清楚后果**，不只是「确定吗？」：删主机说「凭据会一起删掉，无法恢复」，删分组说「机器会回到未分组，机器本身不会被删」，删远端目录说「里面的内容全都会被删」。
- **焦点默认落在确认键上**，回车即确认；`Esc`、点空白、点「取消」都是不执行。
- **危险操作与普通操作分开**：删除类的确认键用 `btn-danger`（红底 + 红光边框），「恢复默认」这种可逆的用普通主按钮。
- **Esc 归上层**：确认框开着时按 `Esc` 只关确认框，底下的连接对话框 / 设置面板不动。为此 ui store 里记了一个 `confirmOpen`，下层对话框的 Esc 处理会先看它。
- **确认框层级最高**（z-index 400），压在连接对话框（100）、通知（200）、右键菜单（300）、设置面板（320）之上。

1. **裁切角按钮**：主按钮用 `clip-path` 切掉右上 / 左下角，不用 `border-radius`；次级按钮用四角描边 + 裁切，呼应参考站 `[ ]` 造型。

## 7. 数据流

**连接建立**
```
用户点 CONNECT
  → 前端 session_connect(ConnectRequest)
  → Rust: keyring 取密文 → 构造 russh client → connect()
  → 认证成功 → 打开 shell channel（term=xterm-256color, 80x24 初值）
  → 打开 SFTP channel（复用）
  → 探测 $SHELL → 注入 cwd 上报钩子
  → 注册会话到 SessionManager → 返回 SessionInfo
  → 前端创建 xterm 实例，绑定 session://data / closed / cwd
```

**终端输入**
```
键盘 → xterm onData → session_write(session_id, data)
  → Rust → shell channel.write(data)
```

**远端输出**
```
shell channel 读 → Rust 任务 → 增量喂入 OSC7 解析器
  → 解析出 cwd 则 emit session://cwd
  → 原始字节 emit session://data → 前端 xterm.write()
```

**文件上传**
```
用户拖文件 → 前端读本地路径 → sftp_upload(session_id, local_path, remote_dir)
  → Rust: SFTP channel.write_file(remote_dir/basename) ，流式读本地文件
  → 每块 emit transfer://progress { transfer_id, transferred, total }
  → 完成后前端刷新目录（清缓存）
```

**错误**
```
任何 Rust 错误 → AppError { code, message, hint }
  → Tauri invoke 返回 Err(序列化后的 AppError)
  → 前端 bridge 统一转成 Error 对象 → Toast 展示 + 标签页状态更新
```

---

## 8. 错误处理策略

| 类别 | 策略 |
|---|---|
| 网络 / 超时 | Rust 侧统一 15s `tokio::time::timeout`，返回 `{ code: "TIMEOUT", message }`；前端显示"连接超时"，保留重试入口 |
| 认证失败 | 返回 `{ code: "AUTH_FAILED", hint: "检查用户名或密码 / 私钥口令" }` |
| 私钥解析失败 | 返回 `{ code: "KEY_INVALID", message: <解析器原文> }`，不打印私钥内容 |
| 远端路径不存在 | 返回 `{ code: "NO_SUCH_PATH" }`，文件面板保留当前路径并提示 |
| 传输中断 | 传输任务标记 `failed`，保留已传输字节数，允许重试 |
| 钥匙串不可用 | 降级为"本次会话有效，不持久化"，UI 明确提示，绝不静默明文落盘 |
| 凭据库主密钥丢失 / 被替换 | 返回 `{ code: "INTERNAL", hint: "凭据库解密失败" }`，提示用户删除凭据库后重新保存密码 |
| 窗体关闭 | 前端 `beforeunload` 触发全量 `disconnect` |

所有错误在 Rust 侧统一经 `AppError` 枚举产出，禁止把 `anyhow` 的裸字符串直接抛给前端。

## 9. 测试策略

| 层 | 手段 | 覆盖 |
|---|---|---|
| Rust 单元 | `cargo test` | OSC7 解析器（分块 / BEL / ST / 截断）、路径拼接、错误映射、传输百分比夹取、shell 钩子脚本生成 |
| Rust 集成 | `russh` 本地 in-process server | 认证成功 / 失败、SFTP 列举与读写、channel 复用与释放计数 |

## 12. 验收标准

1. `cargo test` 全绿；`cargo clippy` 无警告；`npm run build` 无类型错误。
2. 多会话终端可用，标签切换不串数据；切换会话时终端内容各自独立保留。
3. SFTP 文件面板可列举 / 上传 / 下载 / 删除（含非空目录递归）/ 新建目录。
4. 拖拽文件到终端区与文件面板均可上传，且在任意子目录均成功。
5. 关闭标签页后，服务端确认 SSH 连接已释放。
6. 已保存主机的密码不出现在 `hosts.json` 或任何明文文件中。
7. 连接失败时界面显示具体原因与修复提示。
8. 界面通过 §5 的六条转译规则，视觉参考 cindy.cn。
9. `alishiguang/SSH7` 仓库公开可见，README 与 LICENSE 完整。
