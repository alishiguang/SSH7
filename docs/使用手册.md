本文覆盖 SSH7 的全部功能与常见问题。界面术语与软件内保持一致。

## 1. 安装

### macOS

从 [Releases](https://github.com/chuaker7/SSH7/releases) 下载 `.dmg`，拖入「应用程序」。

| 文件 | 适用机器 |
|---|---|
| `SSH7_1.2.0_aarch64.dmg` | Apple Silicon（M1/M2/M3/M4） |
| `SSH7_1.2.0_x64.dmg` | Intel Mac |
| `SSH7_1.2.0_universal.dmg` | 两种架构通吃 |

首次打开若提示「无法验证开发者」，在「系统设置 → 隐私与安全性」中点「仍要打开」即可（SSH7 未做 Apple 公证）。

要求 macOS 10.15 及以上。

### Windows

从 [Releases](https://github.com/chuaker7/SSH7/releases) 下载 `-setup.exe`（NSIS 安装包），双击安装即可。

| 文件 | 适用机器 |
|---|---|
| `SSH7_1.9.0_x64-setup.exe` | 64 位 Windows（Win10 / Win11） |

安装过程中可能遇到两件事，都不是故障：

| 现象 | 原因与处理 |
|---|---|
| **SmartScreen 弹窗**「Windows 已保护你的电脑」 | 安装包**没有做代码签名**，Windows 会拦一下。点「更多信息」→「仍要运行」 |
| **提示缺少 WebView2** | SSH7 的界面跑在 WebView2 上。Win11 自带；Win10 一般随 Edge 已经有了。真的没有的话，安装程序会联网自动补装 |

> 装完之后：主机列表与凭据库放在 `%APPDATA%\com.chuaker7.ssh7\`，
> 与 macOS 的 `~/Library/Application Support/com.chuaker7.ssh7/` 是**同一套格式** ——
> 凭据库就是一个加密文件 + 一个密钥文件，两边格式一致（但它们不在同一台机器上）。

### 从源码构建

需要 Rust 1.82+、Node.js 20+。

```bash
git clone https://github.com/chuaker7/SSH7.git
cd SSH7
npm install

npm run tauri dev     # 开发模式
npm run tauri build   # 打包当前平台
```

产物在 `src-tauri/target/release/bundle/`。

> **依赖说明**：russh 使用 `ring` 作为加密后端，只需要 C 编译器，**不需要 cmake**；
> Windows 上也**不需要 nasm**（ring 自带预汇编好的目标文件）。
> 私钥解析可选依赖系统自带的 `ssh-keygen`（用于把传统 PEM 私钥自动转成 OpenSSH 格式）。

## 3. 建立连接

点侧边栏左上角 **＋ 连接**，或直接点 `HOSTS` 里的主机。

「连接」对话框字段：

| 字段 | 说明 |
|---|---|
| 分组 | 自由填写，留空表示不分组；下拉里能直接选已有的分组。**排在第一个** —— 新建时默认落在当前选中的主机所在分组 |
| 名称 | 显示在标签上的标题，留空自动用 `用户名@主机` |
| 主机 | IP 或域名 |
| 端口 | 默认 `22` |
| 用户名 | 默认取当前系统用户名 |
| 认证方式 | `密码` / `私钥` 二选一 |
| 密码 / 私钥路径 | 密码直接输入；私钥填绝对路径或 `~/.ssh/id_ed25519` |
| 保存 | 勾选后**连接时**一并存进 `HOSTS` 列表；只想存不想连，用下面的「仅保存」 |

三个额外入口：

- **连通性测试**：在真正建连前先测一次，能看到握手耗时，用于快速区分「网络不通」和「认证失败」。
- **仅保存**：只把主机写进列表，**不建立连接**。密码同样加密存在本机，之后从列表里点它再连。编辑已保存的主机时，这个按钮显示为「保存」。
- **编辑主机**：在 `HOSTS` 里右键主机可以修改已保存的信息。

## 4. 认证与凭据安全

### 支持的认证方式

- **密码** —— 明文密码只存在于内存中，连接建立后交给 SSH 协议，不落盘。
- **私钥** —— 支持 OpenSSH 新格式与带口令的加密私钥；传统 PEM 私钥会尝试借助系统 `ssh-keygen` 自动转换。

### 密码与口令存在哪里

保存主机时输入的密码、私钥口令，会被写进**凭据库**。凭据库只有一种形态：**应用目录内的加密文件**。

| 存放位置 | 说明 |
|---|---|
| `app_config_dir()/vault.bin` | AES-256-GCM 加密的密文 |
| `app_config_dir()/vault.key` | 32 字节随机主密钥，权限 0600 |

条目的命名规则是：

```
<主机 id>/password      ← 密码
<主机 id>/passphrase    ← 私钥口令
```

配置文件 `hosts.json` 里**只有主机元数据**（地址、端口、用户名、认证方式、是否有密码），**没有任何明文秘密**。

> **为什么不用系统钥匙串？**
> macOS 的钥匙串按**程序身份**授权，未签名（ad-hoc 签名）的应用每升级一次就会变成新的身份，于是每次都要弹窗索要「登录」钥匙串密码；Linux 上没装 Secret Service 时钥匙串压根不可用。所以 SSH7 统一用本地加密文件 —— 不弹窗、不依赖系统服务、各平台行为一致。
>
> 代价要说清楚：加密文件对**当前用户**可读（能以你的身份运行的进程都能解开），它真正防住的是「明文躺在磁盘上」和「配置文件被同步 / 拷出去」。

> 前端永远拿不到明文密码 —— 包括「克隆会话」这种复用凭据的操作，密码都在 Rust 侧内部传递。

## 5. 会话管理

### 主机分组

侧边栏里的主机按**分组**归拢。分组本身是可以管理的 —— 新建、改名、删除都行。

| 操作 | 怎么做 |
|---|---|
| **新建分组** | 点侧边栏顶部的 **＋ 分组**（在「连接」左边），**列表最下面会多出一行**，光标已经在里面 —— 输入名字回车即建好，`Esc` 取消。**可以是空分组** —— 先把「生产 / 测试 / 本地」建好，往里放机器时直接选 |
| **重命名分组** | 鼠标移到分组标题上，标题右侧出现 ✎，点它就地改名（`Enter` 提交 / `Esc` 取消）。**组里的机器一起改** |
| **删除分组** | 同样悬停分组标题，点 🗑。**机器不会被删**，只是回到「未分组」 |
| **调整分组顺序** | **拖动**分组标题上下移动，落点用一条红线标出来。顺序会存下来，下次打开还是这个顺序。标题上的光标是**抓手**，拖起来不会散 |
| **把机器拖到别的组** | **拖动**主机行到目标分组的标题上，目标标题会亮起红杠，松手即完成。拖回 `// HOSTS` 就是移出分组 |
| **往分组里放机器** | 在「连接」对话框的**分组**字段里选或填一个名字；下拉里能直接选已有的分组 |
| **把机器挪到别的组** | 也可以在主机上点「编辑」→ 改「分组」字段 |
| **折叠 / 展开** | 点分组标题即可；标题右侧的数字是该组里的主机数 |
| **在这个组里新建连接** | **右键分组标题** →「新建连接」。对话框的**分组**字段已经填好这个组，直接填地址就行 |

其它规则：

- 没填分组的主机排在最前面，仍归在 `// HOSTS` 下 —— 这一组固定在最前，不参与排序。
- 分组的**顺序**由清单决定：新建的排在后面，往已有分组里加机器不会打乱顺序。
- 分组名是自由文本，不涉及任何加密，只存在 `hosts.json` 里。
- 右键 `// HOSTS`（未分组）**不出菜单** —— 那组没有"落在哪个组"的概念；从它新建连接默认就是未分组。

### 打开主机

**单击主机不会建立连接** —— 只是把它选中（左侧一道红杠）。想连上得明确说一声：

| 操作 | 怎么做 |
|---|---|
| **开启新会话** | 鼠标移到主机行上，点右侧的 **＋** |
| **开启新会话（另一种入口）** | 在主机行上**右键** →「开启新会话」 |
| **切换到已有会话** | 右键菜单里的「切换到已有会话」（只有这台机器已经开着会话时才出现） |
| **编辑 / 删除** | 同样在右键菜单里 |
| **取消选中** | 再点一次同一台主机 |

这样点一下主机不会莫名其妙开始握手 —— 想开几条连接、开哪一条，你自己说了算。

### 双击主机：在当前窗口开一个会话

**双击主机行**，这台机器就会在**当前窗口**里打开 —— 顶部的标签栏多一个标签，终端连上它。

| 情况 | 会发生什么 |
|---|---|
| 这台机器**还没开过** | 新开一个会话标签，自动连上这台机器 |
| **已经开着** | **不重复开**，直接切到那个标签 |
| 当前窗口里有**好几条**同机器的会话 | 切到其中一条 |

双击不会在同一台机器上开出两个重复的标签 —— 想多开几条，用悬停时的 **＋** 或右键菜单里的「开启新会话」。

### 在新窗口打开

想让一台机器**单独占一扇窗口**（一台机器一个窗口、或者把开发机和生产机分开放），在主机行上**右键** →「**在新窗口打开**」。

| 情况 | 会发生什么 |
|---|---|
| 这台机器**还没开过** | 新开一扇窗口，窗口标题是 `SSH7 · 机器名`，并自动连上这台机器 |
| **已经开过** | **不会再开一扇**，直接把那扇窗叫到前面来 |
| **开着好几扇** | 挑其中一扇叫到前面（不会一次弹出一堆窗） |
| 就在**当前窗口**里开着 | 不开新窗，直接切到当前窗口里对应的那个标签 |

新窗口里的主机列表、标签栏、文件面板都跟主窗口一样，可以继续在里面开别的机器。

> 每扇窗口是**独立**的：关掉一扇窗，它自己开着的连接会一起断开，不会把连接留在后台。

### 新建 / 编辑连接时的默认分组

打开「连接」对话框时，**分组**字段已经帮你填好了 —— 它排在**最上面**，一眼就看得见：

- 从**分组右键**「新建连接」进来的 —— 就落在那个分组；
- 侧边栏里当前**选中**的那台机器在哪个分组，就落在哪个分组 —— 顺着上下文往下建，少改一次字段；
- 没选中任何机器（或者选中的机器没分组）就是 `HOSTS`（未分组）；
- 字段下面有一行小字写着当前的默认值；
- **编辑**已保存的主机时，分组字段带出它自己的分组，**可以改**（清空即移出分组）。

对话框随时可以按 `Esc` 关掉。

### 打开与复用

打开会话只有两条路：**＋ 按钮**和**右键菜单**（见上面的[打开主机](#打开主机)）。单击只是选中。

已经开着这台机器的会话时，右键菜单里会多一项「切换到已有会话」，点它直接切过去，不新建连接；点「开启新会话」则总是新开一条。

### 显式新开一个会话

同一台主机想同时开多条连接时，把鼠标移到 `HOSTS` 的主机行上，右侧会出现 **＋** 按钮，点它即可强制新开一个会话。

### 标签改名与排序

打开的会话只出现在顶部的**标签栏**里（侧边栏不再重复列出），标签可以改名、可以拖动排序：

| 操作 | 怎么做 |
|---|---|
| 改名 | **双击**标签，标签就地变成一个输入框；输入完按 `Enter` 提交，`Esc` 取消，点别处也提交 |
| 改名（另一种入口） | 在标签上**右键** →「重命名」 |
| 调整顺序 | 按住标签**横向拖动**，落点会有一条红线标出位置，松开即生效。标签上的光标是**抓手**，拖动时整个窗口都是抓手 |

改名只改标签上显示的名字，不影响主机记录与连接本身；克隆出来的会话会沿用改名后的名字。

### 右键菜单

在标签栏的标签上右键：

| 菜单项 | 作用 |
|---|---|
| **重命名** | 就地改名（等价于双击标签） |
| **克隆为新会话** | 用同一套凭据新建一条独立连接，凭据在 Rust 侧复用，密码不经过前端 |
| **断开连接** | 断开 SSH，但保留标签，可继续看残留输出 |
| **关闭会话** | 断开连接**并**移除标签；关闭标签会真正回收连接，不会留下悬挂的 SSH 进程 |

> 点击标签本身就已经切换到该会话，因此菜单里不再提供「切换到该会话」。

### 断线与重连

会话意外断了 —— 网络抖一下、远端重启、SSH 会话超时 —— 界面会这样反应：

| 情况 | 会发生什么 |
|---|---|
| **意外断开** | 终端上盖一层浮层说「正在重新连接」，同时自己开始接回去：第 1 次立刻试，第 2、3 次各等 1.2 秒 / 3 秒。接上了就自己恢复，**标签不挪位置、不新开标签** |
| **三次都没接上** | 停下来，浮层给出**失败的原因**（比如「认证失败：密码错误，或本机没有这台机器的凭据」）和「检查用户名与密码后重试」，并摆出两个按钮 |
| **你主动点的「断开连接」** | **不会**自动接回去 —— 你说断就断，它老实断着，不会「我明明断开了，它又连回来了」 |
| **重连成功** | 终端里断线前的屏幕内容**原样留着**，只是换了一条新的连接继续 |

浮层上的两个按钮：

| 按钮 | 作用 |
|---|---|
| **重新连接** | 立刻再连一次。标签仍留在原来的位置，连上了直接恢复 |
| **关闭标签** | 断开并把标签移除 |

> 断线前的输出不会丢 —— 终端始终留在下面，浮层只是盖在上面告诉你「发生了什么、现在在做什么」。

重连用的是当初存进凭据库的那**同一份**凭据（按主机 id 找回来），所以：

- **别删掉主机记录** —— 主机一删，配套的凭据也跟着删了，重连就再也接不回来；
- 密码改了以后，重新连一次即可（重连时用的是库里最新的那份）。

### 关闭标签会真正断开

这是相对旧版的重要修复：旧版关闭标签只是把界面元素移除，SSH 连接一直挂着直到退出程序。SSH7 在会话从列表消失的那一刻就会断开并回收资源。

关闭整个应用时，所有会话会被统一断开。

### 删除前都会问一句

凡是**会丢东西**的操作，点下去都不会立刻生效 —— 先弹一个确认框，说清楚「删什么」和「会丢什么」，你确认了它才动手：

| 操作 | 在哪儿 | 确认框会说什么 |
|---|---|---|
| **删除主机** | 主机行上的 ✕ / 右键「删除」 | 地址、用户名、凭据都会一起删掉，无法恢复 |
| **删除分组** | 分组标题上的 🗑 | 组里的机器会回到「未分组」，机器本身不会被删 |
| **关闭会话** | 标签上的 × / 右键「关闭会话」 | 连接会断开，远端正在运行的进程可能受影响 |
| **删除远端文件 / 目录** | 文件面板里的删除按钮 | 远端无法恢复；删目录会递归删掉里面全部内容 |
| **恢复默认设置** | 设置面板里的「恢复默认」 | 终端字号与界面缩放回到默认值（主机列表和凭据不受影响） |

确认框里：

- `Esc` 或点「取消」= 什么都不发生；
- 焦点默认落在确认键上，回车就是确认；
- 点框外的空白处也会关掉它。

> 一次误点不该换来配置消失 —— 这条规矩对所有删除入口一视同仁。

## 6. 终端

- **xterm.js** 渲染，256 色，支持调整窗口尺寸（远端 PTY 会同步收到新的行列数）。
- **链接识别**：终端里出现的 `http://` / `https://` 地址会自动变成可点击链接。
- **回滚缓冲** 8000 行。
- **光标**为红色竖条，主题与全局设计令牌一致。
- 每个会话有**独立的终端实例**，切换标签互不干扰，切换回来会重新计算尺寸并自动聚焦。

## 7. 设置面板

点标题栏右侧的齿轮图标打开。

### 终端字号

范围 `9 px ~ 24 px`，默认 `12.5 px`，每次调整 `1 px`（设置值按 `0.5 px` 取整）。

也可以用快捷键：

| 快捷键 | 作用 |
|---|---|
| `Ctrl` + `+` | 终端字号放大 1px |
| `Ctrl` + `−` | 终端字号缩小 1px |
| `Ctrl` + `0` | 终端字号复位到 12.5px |

> 快捷键用 `Ctrl` 而不是 `Cmd`，是为了不和 macOS 的 `Cmd + +` 缩放冲突。
> 在输入框里打字时不会触发这些快捷键。

字号变化会立刻生效，并重新计算终端行列数、把新尺寸同步给远端 PTY，远端程序（如 `vim`、`top`）的排版不会错位。

### 界面缩放

范围 `85% ~ 130%`，默认 `100%`，步进 `5%`。影响整个界面（侧边栏、面板、标签、按钮）的文字大小。

### 恢复默认

一键把终端字号与界面缩放一起还原。

### 凭据存在哪儿

凭据的存放位置**不给选** —— 永远是应用目录里的加密文件。理由见[密码与口令存在哪里](#密码与口令存在哪里)。

### 关于本应用

面板底部有一个 **GitHub 图标**，点它会打开仓库页面（`https://github.com/chuaker7/SSH7`）；图标下面一行小字是**当前版本号**，排查问题时可以对着它确认版本。

### 设置的保存位置

显示偏好保存在浏览器 localStorage 的 `ssh7.settings` 下，随应用重启保留。这里**不存放任何凭据** —— 凭据只进凭据库（应用目录内的加密文件）。

## 8. 文件管理

点侧边栏的 **文件** 按钮打开右侧文件面板。

| 操作 | 怎么做 |
|---|---|
| 浏览 | 双击目录进入；`←` 按钮或双击父目录行回到上级 |
| 跳转到指定路径 | 在顶部路径框输入路径后回车 |
| 刷新 | `↻` 按钮 |
| 新建目录 | `＋文件夹` 按钮，输入目录名 |
| 下载 | 文件行右侧的下载按钮，先选本地保存目录 |
| 删除 | 文件行右侧的删除按钮；**删目录会递归删除其全部内容**，有二次确认 |

面板始终跟随当前激活的会话；切换会话后面板内容会重新加载，不会残留上一个会话的文件列表。

### 面板宽度可以拖

文件面板的**左边缘**有一条拖拽把手 —— **往左拖**面板变宽，**往右拖**变窄，文件名太长的时候拖宽一点就看得全了。

- 宽度会**记住**，下次打开还是这个宽度；
- 最宽不超过**屏幕的一半** —— 再宽终端就没地方放了；
- 最窄 240px。

### 面板跟着终端的目录走

终端里 `cd` 到哪儿，文件面板就跟着走到哪儿 —— 不用手动切换路径。

| 情况 | 面板行为 |
|---|---|
| 刚打开文件面板 | 直接落在**终端当前所在的目录**，不是根目录 |
| 终端里 `cd` 到别的目录 | 面板自动跟过去，路径框同步更新 |
| 自己在面板里浏览到别处 | **不会被拽回** —— 你在看别的地方时，面板不跟你抢 |
| 想回终端当前目录 | 点路径栏末尾的 `>_` 按钮，一键跳回 |

面板上方那行 `// SESSION CWD` 显示的是**终端当前所在的目录**（终端里的 `cd` 会被实时跟踪），路径框显示的是**你正在浏览的目录**。两者不一样时，跳回按钮才会出现。

> 目录跟踪依赖远端 shell 的钩子（bash / zsh / fish 各自适配）。如果远端没装钩子或者用了 SSH7 不认识的 shell，`// SESSION CWD` 那行不会出现，面板会固定停在根目录。

## 9. 上传与下载

### 上传的四种方式

1. **拖拽到终端区** —— 上传到远端**当前工作目录**（终端标题里显示的那个路径）。
2. **拖拽到文件面板** —— 上传到面板当前浏览的目录。
3. **文件面板的「上传文件」按钮** —— 弹出系统文件选择框，可多选。
4. **文件面板的「上传文件夹」按钮** —— 选中一个本地文件夹整体上传。

> **松手才上传**：拖动过程中只显示提示层，真正**松开鼠标**之后才开始传输。
> 如果把文件拖到别处松手，不会发生任何上传。

### 目录会被递归上传

拖进来的如果是**文件夹**，SSH7 会自动：

- 在远端创建同名目录（与 `scp -r` 行为一致），
- 递归上传其中所有子目录与文件，
- 在界面上显示**一条**进度条，百分比是整个目录树的总体进度。

符号链接会被跳过，不会把本地目录结构意外暴露到远端。

### 进度显示

传输进度包含文件名、百分比与进度条，**只显示在发起它的那一侧**：

| 从哪儿发起 | 进度条出现在 |
|---|---|
| 文件面板里的下载按钮 | 文件面板底部 |
| 文件面板里的上传按钮 / 拖到面板 | 文件面板底部 |
| 拖到终端区 | 终端区右下角 |

同一件事只说一遍 —— 不会在终端和文件面板各出现一条一模一样的进度条。

- 上传与下载都支持。
- 进度按 `transfer_id` 与界面上那一条记录精确对应，不会出现「大文件 A 的进度跑到了小文件 B 上」。
- 大文件传输时进度事件做了节流，不会每个数据块都刷一次界面。
- **传完 3 秒自动收掉**：进度条只是知会一声，不会一直占着屏幕角落。**失败的不会自动消失** —— 错误得看得见。
- 拖到终端的上传，终端里还会留一行 `✓ 上传完成 <文件名> → <目录>`，那是传输记录，留在回滚历史里。

### 目标目录

- 拖到终端区：远端当前工作目录。如果远端没有上报工作目录信息（例如非 bash/zsh/fish 的 shell），会退回远端用户的家目录。
- 拖到文件面板：面板路径框里显示的目录。

### 失败处理

上传失败会在**发起它的那一侧**打印一行 `✗ 上传失败 <文件名>: <原因>`，对应的进度条会标记为「失败」，同时弹出一条错误通知。失败原因分三类：

| 提示 | 含义 |
|---|---|
| 路径不存在 | 远端目录不存在，或本地文件已被移动 |
| 权限不足 | 远端用户对该目录没有写权限 |
| 其他 | 原样透传底层错误信息 |

## 10. 工作目录跟踪

SSH7 会在远端 shell 里注入一段**只追加**的钩子，用 OSC 7 序列上报当前工作目录，于是：

- 标签上会显示当前目录（`/var/log` 这样的路径）；
- 拖拽上传的目标目录就是它。

钩子按 shell 类型分别注入：

| Shell | 注入方式 |
|---|---|
| bash | 追加到 `PROMPT_COMMAND`（不覆盖原有内容） |
| zsh | 追加到 `precmd_functions` |
| fish | 追加到 `--on-event fish_prompt` 事件 |
| 其他 | 不注入，不影响功能 |

注入是**静默**的：SSH7 在申请远端 PTY 时就把回显关掉，钩子既不会被终端回显，也不会显示在屏幕上；装完立刻把回显还回去，多出来的那行提示符也会被擦掉 —— 屏幕上看起来跟普通会话一模一样。

注入的内容**不会留在远端的历史记录里**。钩子是写进终端输入流的，远端 shell 会把它当成你亲手敲的命令 —— 但 SSH7 会在装完后把这两行从 history 里抹掉，你执行 `history` 看不到它们：

| Shell | 历史里的残留 |
|---|---|
| bash | 没有 —— 装完自动抹掉 |
| zsh | 一行短的（打开「忽略空格」选项那条），装完即关掉该选项 |
| fish / 其他 | 会留两行（这类 shell 没有可用的抹除手段） |

> 早期版本（v1.2.5 ～ v1.8.1）会把钩子留在远端 history 里。如果你的历史里已经有这些记录，可以自己清一次：
>
> ```bash
> # 当前会话（倒着删 —— 删掉靠前的那条会让后面那条的编号往前挪）
> for i in $(history | grep -E '__ssh7_osc7|stty echo' | awk '{print $1}' | tac); do
>   history -d "$i"
> done
> ```
>
> 已经写进 `~/.bash_history` 的那些，下次登录还会出现 —— 那份文件也可以单独过一遍：
>
> ```bash
> cp ~/.bash_history ~/.bash_history.bak
> grep -vE '__ssh7_osc7|stty echo' ~/.bash_history.bak > ~/.bash_history
> ```

如果远端是 `csh`、`tcsh`、PowerShell 等，目录跟踪不会生效，拖拽上传会退回用户家目录 —— 其余功能不受影响。

| 快捷键 | 作用 |
|---|---|
| `Ctrl` + `+` | 终端字号放大 |
| `Ctrl` + `−` | 终端字号缩小 |
| `Ctrl` + `0` | 终端字号复位 |
| `Esc` | 关闭右键菜单 / 设置面板 |

> 需要发送 NUL 时可以用 `Ctrl` + `Space`。

## 12. 数据存放位置

| 数据 | 位置 |
|---|---|
| 主机列表 + 分组清单 | `app_config_dir()/hosts.json` |
| 密码 / 私钥口令 | `app_config_dir()/vault.bin`（AES-256-GCM 加密），主密钥在 `vault.key` |
| 凭据存储偏好 | `app_config_dir()/credential-store.json`（旧版本遗留，v1.8.0 起启动时自动删除） |
| 主机密钥 | `~/.ssh/known_hosts` |
| 界面偏好（字号、缩放） | localStorage，key = `ssh7.settings` |

各系统 `app_config_dir()` 的实际位置：

| 系统 | 路径 |
|---|---|
| macOS | `~/Library/Application Support/com.chuaker7.ssh7/` |
| Windows | `%APPDATA%\com.chuaker7.ssh7\` |
| Linux | `~/.config/com.chuaker7.ssh7/` |

> **关于旧目录**：SSH7 的包名改过两次 —— 早期开发阶段是 `com.igigi.ssh7`，
> 后来是 `com.alishiguang.ssh7`（跟着 GitHub 账号改名），现在是 `com.chuaker7.ssh7`。
> 启动时如果旧目录还在、新目录还是空的，应用会**整个把旧目录搬过去**
> —— 主机列表和凭据库一个字节都不会丢。
>
> 搬不动的时候（比如新目录里已经有数据了），应用**不会**动旧目录里的任何东西 ——
> 数据原样留在那儿，不会被覆盖、也不会被删。
>
> 同时存在两个旧目录时，应用只认领**数据更全的那一个**（通常就是最近那个），
> 另一个原样留着 —— 早期目录里的主机记录和现在的主机 id 不同，硬合并会让
> 同一台机器在列表里出现两行。

## 13. 故障排查

### 连接失败

错误提示里带三段信息：`code`（错误码）、`message`（人话描述）、`hint`（排查建议）。

| 现象 | 排查方向 |
|---|---|
| 连接超时 | 网络不通 / 端口不对 / 防火墙拦截，先用「连通性测试」确认 |
| 认证失败 | 用户名或密码错误；私钥是否与该用户匹配；私钥是否带口令 |
| Permission denied (publickey) | 服务器 `authorized_keys` 里没有对应公钥 |
| 主机密钥已变更 | 服务器重装过 SSH 服务，见下条 |

### 断了以后重连不上

会话意外断开后，SSH7 会自己接回去（试 3 次：立刻 / 1.2 秒 / 3 秒）。连不上时浮层会写清原因，对号入座：

| 浮层上的提示 | 原因 | 处理 |
|---|---|---|
| 认证失败：密码错误，或本机没有这台机器的凭据 | 凭据库里没有这台机器的密码 —— 常见于**主机被删过**（删主机会连带删凭据） | 重新建一次连接，填上密码 |
| Permission denied (publickey) | 私钥与该用户不匹配，或服务器 `authorized_keys` 里没有对应公钥 | 换一把私钥，或把公钥加到服务器上 |
| 连接超时 | 网络不通 / 端口不对 / 防火墙拦截 | 先用「连通性测试」确认 |
| 主机密钥已变更 | 服务器重装过 SSH 服务 | 见下条 |

> **v1.8.2 之前**的版本有个更糟的问题：断线后点「重试」**每次都失败** —— 前端没把「用哪把钥匙」告诉后端，后端取不到密码。现在重连会带上主机 id 与私钥路径，能正常接回去。

### 主机密钥变更被拒绝

SSH7 首次连接会把主机密钥记进 `~/.ssh/known_hosts`（TOFU 策略），之后密钥一旦变化就**直接拒绝连接**并报错。

确认服务器确实重装过、密钥变更属预期后，删掉 `known_hosts` 里的旧记录再重连：

```bash
ssh-keygen -f ~/.ssh/known_hosts -R <主机>
```

### 拖拽没有反应

- 确认拖的是**文件或文件夹**，而不是浏览器里的网页内容。
- 确认松手的位置在终端区或文件面板内。
- 拖拽提示层（半透明遮罩）出现，说明已经识别到拖放。

### 文件面板打不开

文件面板需要**已连接**的会话才可用；会话断开时面板会自动隐藏。

### 文件面板报「内部错误」

v1.2.0 及更早版本有一个 SFTP 子系统没启动的缺陷，会导致文件面板一律列目录失败，**v1.2.1 已修复**。

如果升级后仍报错，SSH7 会在错误下方用小字显示**原始错误详情**（等宽字体），据此判断：

| 详情关键字 | 含义 | 处理 |
|---|---|---|
| `NoSuchFile` | 远端路径不存在 | 返回上级目录重新浏览 |
| `PermissionDenied` | 账号对该路径没权限 | 换一个目录 |
| `Failure` | 服务器拒绝了这个操作 | 确认远端磁盘没满、路径没被占用 |
| `timeout` / `TimedOut` | 服务器没响应 | 检查网络与 `sshd` 是否正常 |

### 终端是空白 / 没有输出

- 远端 shell 可能还没输出任何内容，先按一次回车。
- 会话刚建立时，SSH7 会把连接期间缓存的输出补发到终端，正常情况下不会丢首屏。

### 目录跟踪不生效

远端 shell 不是 bash / zsh / fish 时不会注入钩子，属预期行为，详见[工作目录跟踪](#10-工作目录跟踪)。

### macOS 弹「SSH7 想要访问你的钥匙串」

从 **v1.8.0** 起，SSH7 **完全不使用系统钥匙串** —— 密码只写进应用目录里的加密文件，程序里连钥匙串的代码都没有。正常使用**不应该**再出现这个弹窗。

看到它只有两种可能：

- 装的是**旧版本**（v1.8.0 之前）—— 升级到新版即可；
- 你是从**更老的版本**升级上来的，当时密码存在钥匙串里。

第二种情况这样处理：

1. 用旧版本打开一次设置面板，把凭据存储方式切到「本地加密文件」（v1.2.2 ~ v1.7.x 有这个选项）—— 密码会被搬进加密库，钥匙串里的副本同时删掉；
2. 升级到 v1.8.0 之后，SSH7 再也不会碰钥匙串。

> v1.8.0 之所以**彻底删掉**钥匙串，不只是因为 macOS 弹窗：钥匙串是**平台专属**的 —— Windows 走凭据管理器、Linux 走 Secret Service，三套 API、三套失败模式。跨平台产品背着这种差异只会处处踩坑，所以统一用一份加密文件，各平台行为完全一致。

## 14. 安全说明

- **密码与私钥口令只进凭据库**：统一是应用目录内的 AES-256-GCM 加密文件（主密钥 0600 权限单独存放），不依赖系统钥匙串。`hosts.json` 里永远只有主机元数据。
- **前端永远拿不到明文凭据**，包括克隆会话时 —— 复用发生在 Rust 侧内部。
- **主机密钥走 `known_hosts` 校验**：首次记录，之后变更即拒绝，避免中间人攻击。
- **私钥内容只在 Rust 内存中处理**，不写日志、不进错误消息。
- **严格 CSP**：前端不加载任何远程脚本，资源全部来自本地。
- **会话 ID 用 UUIDv7**，不会因为时间戳碰撞而串号。
